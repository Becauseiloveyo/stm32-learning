## 按验收条件核对

| T07 条件 | 可执行证据与解释 |
|---|---|
| 断网状态变化后不补发过时提醒 | 实际原始观测先产生一条合格研究提醒，再开夹／换批次；重连提交最新 head 与积压后旧任务取消。另测旧上传包晚到不能回滚 head、接收前重查及旧卡片 sync 失效。 |
| 重复提交不重复提醒 | 服务端按不可变 ID 保存，接收端按域和 episode 去重；确认丢失、推送后／接收保存后进程中断再试不增加同键提醒。连续情景的同轮 tick 只静默更新。 |
| 重启不复用已发布事件身份 | 生命周期 event_seq 和 boot_seq 持久递增；新 boot 清证据、要求重新稳定采样。提交前／后真实子进程退出与 reopen 覆盖回滚和已提交边界，旧写者被拒绝。 |
| 区分保存、推送、接收和已读 | 四阶段分别存储；手机不可达时只有模拟推送接受，接收和已读保持空。显式模拟 read 不冒充真实用户已读。 |
| 未标定研究事件不冒充收衣 | 唯一允许的提醒为 RESEARCH_REVIEW；外层及上游授权严格为 false。原始样本缺失、伪造 assessment、重复弱事件不能启用收衣分支。 |
| 时间和配置明确 | TTL 锚定原有效弱周期结束；tick／重发不刷新。未来时间跨 tick 继续拒绝；等号过期；要求与应用配置分开，实际 configure 后必须重新安装和采样。 |

本轮还验证默认有限 outbox、满队列独立安全 head、持久摘要损坏拒绝、错误 ACK 整体回滚，以及旧／重复 ACK 不删除新消息。满队列锁存停止并不是长期运行策略，需后续评估。

## 已见反例与整合修正

协调检查发现多事件保存 ACK 成功处理后再次收到同一份 ACK 会报 unknown acknowledgment。最终实现对已发行且不在队列的旧 ID 无操作，对仍在队列的摘要不匹配整体回滚；未发行的新 ID 拒绝。原型没有为此增加无界 ACK 历史。

服务端不可能知道设备尚未上报的离线变化：先上传研究复核，再离线开夹，TTL 内仍可能按最后已知状态提醒；同步后旧卡片失效。角色与协调检查都明确保留这个反例。验收保证限于最新已同步状态、有效期与串行本地处理，不能宣称全球实时新鲜或撤回所有 OS 通知。

整合中一次验收虽有 59 项测试通过，但共享脚本在运行期间被恢复的角色对话修改，来源稳定检查正确拒绝通过。该失败记录保留为 [T07-interrupted-run.json](T07-interrupted-run.json)，旧 `results/accepted/` 仅为历史。角色停止写入后，协调者整合 outbox 摘要及新检查、生成独立 `accepted-v2/` 并重新验收；当前只引用本页指定的稳定版本。

## 不由本轮结论覆盖的事项

1. SQLite 只证明当前主机进程崩溃语义；MCU Flash、物理掉电、磨损、磁盘满、坏块、存储回滚和克隆均未验证。生产者身份需外部分配。
2. 通知实际调用 T04 Python；T06 仅给映射，未在消息链路中执行 C，也未实现 STM32 驱动／完整固件。有限内存、历史回收、锁存恢复尚待设计。
3. 未集成 T05 设备无线能量准入与日额度；服务端重试不代表设备省电，太阳能／峰值和续航仍无实测。
4. 没有真实身份认证、TLS、账号绑定、服务器、手机 App 或厂商推送；模拟接收／已读不代表手机后台送达。服务／接收历史及 Python 控制器历史无界，服务串行，未处理集群竞态。
5. 真实衣物标定、阈值、准确率与创新优势未获得证据。measured_at 只指弱证据周期，不是完整测量历史。
