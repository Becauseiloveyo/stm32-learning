## 审查中修正的问题

1. 初版扩展精度均值在精确门限附近与 Python 产生舍入分类差异。固定 36 字整数累加器消除了已见反例，保留原门限；新增精确门限、相邻浮点值和独立均值检查，没有用较宽的数值容差掩盖分类错误。
2. Python 到 ctypes 的计数转换可能将 `2**32+3` 绕回 3。所有无符号配置计数先核对类型与范围，超范围显式拒绝，configure 事件也不能借该路径产生合法配置。
3. 本机 Windows 汇编器无法可靠处理中文绝对输出路径。构建仍在项目内，通过 Unicode cwd 和 ASCII 相对输出路径完成，不移动工程、不改全局 PATH、不安装工具。
4. 最小周期间隔为 0 的输入明确拒绝；协调测试使用当前有效配置的 30 秒间隔。两边时间域和参数仍须由调用方正确关联。

## 必须保留的限制

这是 `T06-C99-BOUNDED-1` 支持域，不是任意 Python 输入的无差别替代。身份只支持最多 32 ASCII 字节；样本、时长、计数和历史上限见接口。输入值的类型规范化摘要与原始 JSON 字节签名语义不同。低于 epsilon 的极小储能反例中，C 明确拒绝未付清启动；该保守不同已经保留测试，不能宣传全域完全等价。

本机 `hs_machine` 为 9616 字节，默认 141 行观测为 11280 字节，两者合计 **20912 字节**；还需输出、配置、能量结构、调用栈和设备层。最大 512 行输入本身为 40960 字节。固定容量不代表适合小内存 MCU：64 条事件历史／16 个周期的保守原型会在运行中耗尽；耗尽锁存是明确故障处理，没有实现长期回收。

测量核心最大已列单函数栈帧为 912 字节，能量原语为 480 字节；单帧不是调用链总栈，所有测算都不含未列数学库、RTOS／中断、传感器、网络及目标 ABI。double 与精确求和的实际时延和功耗未测，不能以电脑速度推断 STM32 上的实时性。

没有完整 C 请求队列／策略控制器、实际 RTC、唯一身份来源、非易失原子存储、掉电恢复、驱动或固件链接脚本。日额度不能在真实 reboot 后随意归零，冷初始化不能用来绕过防重放。无实物判干、太阳能续航或手机送达证据。U06 得到有界行为与资源证据，长期回收／掉电一致性仍保持开放。
