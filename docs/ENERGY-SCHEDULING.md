## 2. 能量账本与完整动作准入

以 Wh 为账本单位，W 积分秒数后除以 3600；执行器 J 也除以 3600。每段记录请求负载、实际供给、实际未供负载、转换损失、收能、储能及弃能。设该段起止储能为 `B0/B1`，电池侧收能为 `H`，实际负载侧供给为 `L`，弃能为 `S`：

```text
B1 = B0 + H - L / eta - S
conversion_loss = L / eta - L
actual_unmet_load = requested_load - L
0 <= B1 <= capacity
```

同一秒内的连续功率按等效平均处理，背景优先供给；满电时超出容量的能量弃掉。启动和气窗的零时长脉冲只使用当时储能，不能借该秒后续收能。相同模式／动作／阶段／负载与环境的相邻秒合并为区间，但开关、启动和模式边界单独保留；原始账本仍足以逐段核对守恒。此模型没有电池内阻、瞬态跌落、峰值电流、执行器脉宽、充电温度／限流／尾充或效率曲线，不能用于峰值供电验收。

默认完整测量的增量动作能量为：

```text
阶段采集 = 0.002 × (30 + 20 + 90) = 0.28 J
风机     = 0.2 × 20 = 4.00 J
气窗     = 0.05 + 0.05 = 0.10 J
合计     = 4.38 J = 0.001216666667 Wh（负载侧，未含背景）
```

在启动时要求：

```text
当前储能 - stop_wh >= (完整动作负载 + 完整时长内运行背景及杂项) / eta
```

默认测量预留 `0.001484749455 Wh`，无线按 20 秒最坏超时预留 `0.003929193900 Wh`。均是阈值以上的电池侧预算，包含全过程背景；不借未来太阳能，不按未来无线成功或原始判定决定是否准入。预留是准入检查，支出仍逐段发生，未花部分不会被虚扣。任何完整动作还必须能在请求期限和仿真截止前完成，恰好在截止完成允许。日均规划的 1.3 倍裕量和 0.05 Wh 向上取整不混入本层已付能量。

气窗于周期第 30 秒打开，第 50 秒关闭。若打开期间被安装事件等打断，仅支付已执行阶段、已用风机和一次安全关闭；打开前取消无需关闭费，已关闭后取消也不再收费。中断不产生 `finish_cycle` 或有效计数，但保留已付成本和旧预留结束时间。正常准入不变量保证完整动作及安全退出可支付；若模型假设被破坏出现供能缺口，记 `interrupted_energy`，不能伪造完成。物理断电时能否安全闭窗还需硬件验证。

没有启动的请求属于服务未完成，不计作实际电气未供负载，避免重复计账。六组主场景实际未供负载为 0，仍有大量未服务请求；专门的零储能测试则验证停止背景的实际缺口和零完成记录。

## 3. 时序、证据和故障恢复

每个模拟秒按以下顺序处理，所有 T04 事件使用真实整数秒和严格递增的当前启动单调时钟：

1. 若此前停止且满足重启阈值，支付启动费并发 `boot`；接收当秒安装控制。新安装先取消旧任务，因此恰好发生在旧周期结束秒的安装仍会取消该旧周期。
2. 完成到期的动作：测量发送含新原始观测的 `finish_cycle`，无线检查当次已观察到的连接过程。
3. 检查低电量停止与模式迟滞，再终结已到期的等待请求。**同秒完成优先于低电量停止**：恰好用足准入预算的完整周期先记完成；T04 的事件槽已占用时，停止／clip 延至下一实际秒，可能多付至多一秒背景。停止阈值是软件保留线，不是物理切断点。
4. 接收当秒外部请求，选取一个动作；测量优先，无线随后，各类内关键请求优先，再按到达时间和 ID 排序。活动期间不并发第二个动作。
5. 必要时发 `recover` 或 `tick`，随后支付 `[t,t+1)` 背景和活动能量。截止秒仍处理到期完成和必要的时钟维护，再将剩余等待请求标为 `horizon_censored`；截止后不运行负载。

一个墙钟秒至多发送一个 T04 事件。若 `boot` 占用安装事件的同秒槽，明确排到下一个实际秒；不加 epsilon 假装时间前进。安装稳定等待、最小周期间隔、完成窗口和配置指纹均由真实 T04 约束。中断后旧周期的结束墙钟加最小间隔仍不可提前重用；本模拟器还跨新启动保留该墙钟预留。

只有付完完整周期才为**该周期**生成原始观测，并使用 `OBSERVATION_KEYS` 所定义的输入字段提交给 T04；不注入 WEAK／UNKNOWN 等预先判定。观测条件按周期开始时的输入区间选取，作为该周期的固定模型参数，非跨周期真实晾干轨迹。默认 `surface_activity=0.60`、`noise_rh_pct=0`，合成模型种子 `20261023`；同种子重复场景不是独立实物测量，也不能靠重复低变化信号获得标定。

`budget_completed` 只表示周期按预算执行完。`quality_valid` 还要求真实 assessment 非 UNKNOWN；它也不表示已干。UNKNOWN 周期照常支付能量，不能累计弱证据，T04 转入 FAULT。模拟采集控制器在下一个可用事件槽显式 `recover`，重新等待稳定，后续请求再产生新周期；同一失败请求不会自动重用旧观测。

停止会取消所有旧任务并使安装失效；新启动产生新 `boot_id`。停止时到来的请求记 `missed_offline`，安装记同名遗漏状态，均**不缓存后补**；所有外部请求仍留在审计分母内。重启后必须重新观察到明确的可信模拟安装事件才能恢复测量。仿真器保留的墙钟预留和无线日额度属于进程内状态，**跨模拟 boot 保留不等于已实现真实掉电持久化**。真实时钟、存储损坏、写入原子性及安装感知尚未实现。

闲置证据严格超过 1800 秒才过期，等于边界不清除。调度会在期限刚超过时发 tick，包括恰好落在仿真最后一秒的边界；活动周期内按上游定义处理。新批次／重装／停止清除链与闲置过期计数分别保留，不能把所有清除都称作自然过期。

无线准入总按 20 秒计算。最初连续 6 秒可用才在第 6 秒确认；若期间失败，即使随后恢复也支付到 20 秒超时，之后才退避再试。每日额度按每个实际跨度日分摊最坏尝试预算，跨午夜不能全部挤入第一天；已付无线电池支出累加，启动不清零额度。成功 ACK 只是该次模拟联网确认，未接入 T07 的服务端投递、用户收到或幂等协议。

### 等待、失败与删失

P95 只针对成功请求，使用排序后向上取整的第 95 百分位。未服务请求另外记录终结等待（到取消／过期／掉线遗漏／截止的时间）及**截至仿真结束仍无服务结果的随访秒数之和** `sum(horizon-at_s)`。后者保留被即时判定掉线遗漏的请求，不是成功延迟估计。终结等待为 0 绝不表示即时成功。

下表三元组单位均为秒：“成功 P95／未服务请求终结等待和／未服务请求随访和”。六组主场景的截止删失数都是 0，但所有未服务请求仍在分母及随访中；单元场景另验证真正的 `horizon_censored`。逐请求状态、阻塞原因、到达／截止／终结时刻保存在 `service.json`。

本轮 Python 3.14.6 下 28 项自检通过，含 20 组种子 `20261025` 的参数组合、两策略各一遍；主场景种子另为 `20261023`。检查覆盖解析守恒、满电弃能、空储能真实缺口、准入等号和略低、恰好完成先于停止、有限期限／删失、完整 140 秒与原始 assess、配置不变、严格事件时钟、安装／最小间隔、气窗三种取消边界、旧窗口跨 boot 保留、失败联网付费／限次／退避／跨日预算、迟滞、UNKNOWN、未来输入不改变前缀、迟到太阳能不能补过去的完成，以及闲置过期恰落于仿真末秒。

日均交叉对照将本轮新增阶段增量和启动项明确设为 0，以既有 36／144 周期及 28 次成功联网重新计算，分别得到负载侧 0.097／0.220 Wh，与当前 `analysis/energy_budget.py` 对齐；不能拿关闭新增项后的数值当作本轮实际总能量。

重新生成后，`--verify` 检查 38 个数据产物哈希，独立重放保存的 **8734 条真实 T04 事件**，再从保存的输入重算 **6 组、12 次完整能源仿真**并逐字节比较；63,873 行原始观测保存在事件中。全程不写文件。主场景总账最大绝对守恒残差约 `1.55e-11 Wh`，单区间最大约 `6.64e-13 Wh`，均低于自检 `1e-9 Wh` 容差。结果合计 31,744,130 字节（含清单），不是仅汇总。

清单 `input_sha256` 相对项目根，`source_sha256` 相对 `research/energy_t05`，`output_sha256` 相对 `results`；包含实际读取的上游源码、协议／状态机清单、契约／设计／任务文档和历史能源参考的指纹，以及配置快照、能量参数、单位、种子、假设和合成标签。生成前先校验已验收上游来源，校验命令还核对当前场景定义和完整清单，不能静默使用旧结果。说明文档不作为可执行源码参与清单自引用。
