# 正式 T04：多周期证据状态机

T01–T03 已由协调者验收，用户要求继续下一步。本角色只实现 ROADMAP 的 T04，协调者维护全局状态并独立复核。

## 输入与所有权

- 读取 AGENTS、PROJECT、STATUS、TEAM、本任务书和 ROADMAP 的 T04。
- 只读输入：MEASUREMENT-CONTRACT、MODEL-VALIDITY 第 4–8 节、当前 theory/protocol.py、model.py 的 assess 与 EvidenceTracker，及总体架构第 7 节／异常处理必要部分。
- 旧架构中的接近干燥／建议收衣是未来产品背景，不能覆盖当前研究边界。无实物标定时始终 collection_authorized=false，无收衣完成事件。
- 本轮唯一写入范围：`research/state_machine/**`、`docs/STATE-MACHINE.md`、`docs/team/reports/measurement-t04.md`。
- 当前 theory/**、MEASUREMENT-CONTRACT、MODEL-VALIDITY、其他研究目录和旧报告均只读。允许导入已验收的单周期实现；新多周期层独立封装，避免改动上游来源与已验收仿真。
- 不改全局控制文档、根 README、工具、协调测试收据；不创建对话／代理、发消息、提交／重置／清理、采购或部署。

## 有限交付

1. 用标准库实现可在电脑运行的确定性多周期状态机，文档定义安装／稳定／测量／待确认／异常等状态和转换、事件语义、拒绝原因、恢复路径及连续证据何时归零。稳定等待的配置仅是研究时序假设，不宣称证明实物稳定。
2. 周期附加批次 ID、启动／重启时间域、周期身份、开始与结束时间和配置身份。区分相对周期秒数与设备单调时间，明确允许的重复／乱序／跳变／超时处理。配置身份覆盖协议、Gates 和状态机策略／版本，不能只覆盖协议却遗漏门限变化。
3. 多周期有效性判定必须由合法原始观测调用当前 assess 得出，不直接信任调用者传来的“弱信号”或 collection_authorized。观测真值／模拟参数不得进入决策。
4. 换衣批次、开夹／重新安装、配置变化、异常窗口、重启均不得继承之前的弱证据。完整周期重发不能重复计数；不能靠更换消息 ID 将同一时间窗重复累积。旧批次或旧启动域延迟到达要有明确拒绝路径。
5. 处理缺数据、周期未完成、时间重复／倒退／大跳变、重启、批次切换；强信号／UNKNOWN 的行为与未标定证据边界一致。定时等待、连续次数及间隔等集中配置，标注单位、有效范围、假设性质。不要加虚构的物理有效性门限。若不恢复持久化证据，明确重启清空、重新安装／稳定，列出调用方需提供的唯一身份和可信时钟条件。
6. 交付确定性事件重放入口 `research/state_machine/run.py`（生成及 `--verify` 只读重算）、可读情景和 tests。覆盖正常多周期、换衣、开夹、无效／缺样、重发、旧批次延迟、时间跳变、配置变化、重启等验收反例。测试以行为不变量、事件序列及现有真实判定器重放为主，不只镜像内部实现。
7. 结果放在 `research/state_machine/results/`，manifest 记录 source_sha256（相对研究目录）、input_sha256（相对项目根）、output_sha256（相对 results）、协议／配置快照、单位、情景假设和种子／无随机性。保存输入事件及每步输出，使第三方能重放。标记 SYNTHETIC_UNCALIBRATED，所有收衣授权 false。
8. 正式 STATE-MACHINE 文档列出当前已实现保障、依赖调用方的条件和不能保证的物理事项。说明旧 EvidenceTracker 只是单周期计数基线，新入口承担批次与重启边界；不修改被上游清单引用的旧文件。未来 firmware、调度、推送接口仅记交接需求，不执行 T05/T06/T07。

## 检查与停止

运行拥有范围的测试、生成与只读复算，并在新报告记录实际命令、数值／情景数量、文件、限制和协调复核入口。不要重跑无改动上游测试。若确有必要改只读接口，先在报告提出阻塞和最小变更，由协调者处理。

提交报告和最终回复后停止，主线验收由协调者完成。协调者将新增独立 state_machine 收据和清单恢复检查；不由本角色写全局状态或测试收据。
