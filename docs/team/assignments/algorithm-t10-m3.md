# T10 M3：中央观测与衣物状态的最小物理适配

2026-10-29 编制。延续现有 Terra 算法对话（gpt-6.1-terra / xhigh）。当前只准备任务书，是否派发由 STATUS 决定。

## 为什么做这一包

M1 能在给定参数下推进衣物状态，M2a 能检查中央观测是否适用，M2b 能计算合成情景的目标时间。但尚无守恒的“衣物水分—中央局部空气—温湿度读数”映射，不能据此用观测校正水量。这是原 T10 观测适配任务的缺口，不是新增产品功能或新增测点。

## 最小输入与所有权

先读 AGENTS、PROJECT、STATUS、TEAM、本任务书；运行 project_status.py 及 M1/M2a/M2b 的 --check-receipt（后者为 tools/check_garment_eta.py）。读三个协调验收文件、GARMENT-OBSERVATION 的未闭合边界、GARMENT-ETA 的 scenario_only 限制、设计补充第 5 节、MEASUREMENT-CONTRACT 和 PROBE-CONCEPTS/MODEL-VALIDITY 的相关气路/壁源部分；按实际需要读 theory 的对应源码，避免全仓库重载。

唯一写入：`research/garment_prediction/observation_m3/**`、`docs/GARMENT-OBSERVATION-PHYSICS.md`、`docs/team/reports/algorithm-t10-m3.md`。M1/M2a/M2b 已验收源码、配置、报告、说明和清单只读；不改全局或旧研究记录，不提交、采购、部署、创建代理或主动联系其他对话。先核对这些包的收据指纹。

## 实施内容与验收

1. 先写明映射的状态、输入、边界、单位与最小适用域。沿用中央单位置及已有局部空气温湿度研究；不改成直接电学测湿、不增设传感器。两计算区和中央的关系只能作为明示假设，不能设为默认真相。
2. 显式区分开放面积与中央覆盖面积。衣物在覆盖处损失的水量必须与局部空气收到的量一致，不能在 M1 完全开放蒸发之外再多扣一份覆盖蒸发。腔体换气与外界通量相抵，若引入壁源需明确有限库存或外部边界，不能凭空造水。
3. 量化是否能在短窗口使用受限等温近似。可以从明确的固定温度子域开始，但需解释维持该近似所需的热边界/忽略项，不能将其当真实衣架完全能量闭合，也不把示例恒温条件变成新增加热硬件。若保留温度动态，则须写出一致热账，不能只拼接两份旧方程。
4. 生成端可以读取状态以生成合成观测；消费端只使用当时可得的温湿度、时间和有效性信息。观测响应/延迟/偏差的参数必须说明来源或合成假设；未知值不是零。接触证据继续采用 M2a 的外部覆盖时段，不声称实现了自动接触检测。
5. 先验证零覆盖/零交换等退化边界、总水量账、稳态/过渡、步长/独立参考、缺失/环境变化/超域暂停，再讨论能否给出约束局部水量的信息。只有有依据的模型关系才能筛选集合；未测区域仍受 M2a 的多解反例限制。
6. 不要求强行得到唯一含水量。给出不同材料/漏风/覆盖或初值相容的反例及适用边界；若当前参数不足以闭合，指出具体方程/缺参，不用任意线性权重或读取隐藏真值凑出结果。不要把合成映射称实物校准。
7. 新配置、单位、来源、种子、运行命令及指纹齐备；产物只在本包目录。所有结果 SYNTHETIC_UNCALIBRATED，collection_authorized=false；不改 C、App、能源/雨情或通知接口。
