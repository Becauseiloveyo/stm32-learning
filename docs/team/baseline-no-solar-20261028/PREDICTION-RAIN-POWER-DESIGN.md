# T09：干燥预测、雨情提醒与供电设计补充

日期：2026-10-27。范围来自用户最新要求：以课程设计为当前交付场景，无实物测试条件，建立可解释物理模型，补全甩干初值、面料不确定性、雨情、通信、功耗、太阳能面积和 STM32 尺寸设计。武汉作为示例，用户希望方法可迁移到其他地区，未指定阳台朝向或玻璃内外位置。

## 1. 本轮设计结论

1. 增加“衣物水分与温度”的慢过程模型，原短窗口模型继续负责局部观测解释；不能把原有弱信号计数当作剩余干燥时间。
2. 初版不强制自动识别纤维名称。以未知面料的参数集合、厚薄/层数/初始含水量区间计算条件时间范围；衣物标签只帮助缩小先验，不覆盖观测异常。
3. 天气预报与光照、湿度变化用于风险提示。本地表面润湿/雨滴输入独立运行，不能因为没有预报或白天很亮就禁止触发。
4. 课程设计采用 STM32 本地采集/状态处理、无线模块间歇上传、电脑本地服务模拟远程链路；真正离家提醒仍需可达服务和手机推送。互联网点对点不是本轮默认方案。
5. 先减少联网与主动换气次数，再计算太阳能面积；太阳能板可与衣架主机分开固定，使朝向不随衣服摆动。
6. 武汉样例六种候选中，南向、相对水平倾斜 30° 的 2023 年辐照总量最高。这不是全国最优角度，也未包含楼房、玻璃和衣物遮挡。
7. STM32 芯片本身可以很小，但原候选 U031 的 12 KB SRAM 小于当前 C 原型约 20.4 KiB 的主机输入加状态基线；不能直接宣布可装入该芯片。

## 2. 先定义预测对象

区分三个问题：

- **当前局部状态**：探头附近的水汽观测是否可信，是否存在明显来源。
- **条件剩余时间**：在给定未来环境情景和参数集合下，模型何时达到指定含水条件。
- **真实收衣建议**：上述条件与实际可收取状态是否具有独立标定关系。

课程设计当前可完成前两项的模型与软件实验；第三项保留待实测，不因仿真曲线平滑而自动获得授权。

定义干基含水量 `X = m_water / m_dry`，单位 kg/kg。湿基含水量 `w = X/(1+X)`，两者不能混用。举例：`X=0.5` 表示 100 g 干布对应 50 g 水，不是整件衣物质量的 50% 为水。

“已干”不能定义为零水分，也不能只定义为变化率小：潮湿环境下可出现水分仍多却蒸发很慢的状态。未来产品端点应由独立参考确定，例如规定条件调湿后的含水量加允许过量，且材料、用途和环境适用范围明确。仿真可以设置显式的演示目标 `X_target_sim`，但必须标为合成目标，不能搬用烘干机或某论文的终点作为本产品标定。

## 3. 甩干后的初值

甩干主要改变初始水量 `X0`，不消除面料、织物结构、层数和厚度的影响。机械脱水论文区分干基剩余水分、自由水和较难移除的水；其试样与实验装置不等于家庭洗衣机的所有衣物。[S03](references/T09-sources.md)

课程设计输入建议为：

| 输入 | 初版处理 | 不允许的推断 |
|---|---|---|
| 是否经过洗衣机甩干 | 默认场景为已甩干，另设未充分甩干压力情景 | 已甩干意味着固定含水量 |
| 转速/程序（用户可选填写） | 作为先验信息，缺失不阻止运行 | 用转速唯一换算 `X0` |
| 干布质量或面密度×面积 | 已知时输入，否则用声明的区间 | 将湿衣总质量当干布质量 |
| 厚度、层数和重点部位 | 设置薄区与慢干区 | 单点读数代表所有接缝、口袋 |
| 面料标签 | 可选棉/化纤/混纺/未知，记录来源 | 手机照片或简单湿度曲线能可靠识别所有混纺 |

第一轮可用 `X0∈{0.3,0.6,1.0} kg/kg` 作为**人为选定的敏感性情景**，不是文献给出的所有甩干衣物范围，也不是概率分布。已甩干后仍有明显滴水的情况需要排液项，不能把排出的液滴全算成蒸发。

## 4. 热量与水分耦合模型

下面是项目的低阶工程模型建议，依据质量、能量守恒及公开织物蒸发研究组合，不是声称某篇论文已验证这套衣架模型。先实现未覆盖织物基线，再处理探头覆盖影响。[S01–S04](references/T09-sources.md)

### 4.1 状态与输入

将衣物分为普通薄区和接缝/多层慢区 `j=1,2`，各自具有 `X_j(t)` 和温度 `T_j(t)`。这比一个全衣平均含水量更容易表现表面先干、厚处滞后的情况，但两个区仍是近似。

外部输入为环境温度 `T_a`、相对湿度比例 `φ_a`、衣物附近有效风速 `v`、衣物平面的太阳辐照 `G_g`、周围辐射温度 `T_sur`，以及被衣物实际截获的液水输入 `R_j`。缺失的风速和日照保留区间，不填入零值或天气站数值冒充测点值。

| 符号 | 单位 | 含义 |
|---|---|---|
| `m_d,j` | kg | 区域干布质量 |
| `X_j` | kg/kg | 干基含水量 |
| `A_e,j` | m² | 有效蒸发表面积，注意单面/双面 |
| `A_proj,j` | m² | 对太阳的有效投影面积，不能直接等同双面蒸发面积 |
| `A_h,j, A_rad,j` | m² | 对流与长波辐射面积 |
| `r_a, r_i` | s/m | 外部传质阻力与内部等效阻力 |
| `h_j` | W/(m²·K) | 对流换热系数 |
| `c_d, c_w` | J/(kg·K) | 干织物与液态水比热 |
| `L_v` | J/kg | 汽化潜热 |
| `α_j, ε_j, a_w` | 无量纲 | 短波吸收率、长波发射率、水活度 |

### 4.2 水汽交换与水量守恒

```text
ρ_sat(T) = p_sat(T) / [R_v (T + 273.15)]
ρ_a      = φ_a ρ_sat(T_a)
J_j      = [a_w(X_j,T_j;θ_j) ρ_sat(T_j) − ρ_a]
           / [r_a(v,geometry) + r_i(X_j,T_j;θ_j)]
M_j      = A_e,j J_j
m_d,j dX_j/dt = −M_j + R_j − D_j
```

`ρ` 单位 kg/m³，`J` 单位 kg/(m²·s)，`M,R,D` 单位 kg/s。`D_j` 是排液。负 `J` 表示吸湿/凝结方向，不能无条件截成零；需要与水活度/容量边界一致处理。库存不能变负，数值积分触及零水量时应定位事件并停止正向出水，不能靠静默裁剪掩盖守恒误差。

`r_i` 随干燥增大可表达内部供水受限；`a_w` 则描述可供蒸发的水汽势。二者同为未知时不能自由拟合到任何曲线后就认为参数真实。初版固定一个材料函数族，只在有信息时估计极少量有效参数，其余作为区间。

无风不等于不干：`r_a` 需要包含自然对流/扩散基线，不能简单令传质系数与风速成正比而在零风时归零。湿表面蒸发伴随降温，因此不能总以环境温度代替 `T_j`。

### 4.3 能量守恒

未覆盖区域的集总能量式为：

```text
C_j(X_j) = m_d,j (c_d,j + X_j c_w)
C_j dT_j/dt = α_j G_g A_proj,j
              + h_j A_h,j (T_a − T_j)
              + ε_j σ A_rad,j [(T_sur+273.15)^4 − (T_j+273.15)^4]
              − L_v M_j
              + c_w R_j (T_rain − T_j)
```

此式假定排液温度与该区域相同；若显式加入跨区液水迁移，必须成对加入相应水量与焓，不能只在一侧增加水分。初版两区独立蒸发，暂不加入未约束的横向迁移。

衣物颜色/涂层进入 `α`，风影响 `h` 和 `r_a`，材料/厚度进入 `C、a_w、r_i`，环境湿度进入水汽驱动力。辐射面积和有效天空/周围视角应在 `A_rad、T_sur` 中说明，不能把阳台屋顶下的衣物当作完全暴露天空。

这里把集总水分交换的潜热近似为液态水汽化潜热，未单独建模纤维结合水的吸脱附焓、织物各向异性和液水毛细再分布。尤其在后期干燥，这些简化可能产生模型误差；需要作为挑战情景或后续修正，不能把该低阶式称为完整织物物理模型。

### 4.4 参数闭合和数值边界

完整物理定律较成熟，真实衣物的参数并不因此自动已知。初版允许单独标注的合成闭合，例如：

```text
a_w(X) = 1 − exp[−(X/X_b)^n],   X_b>0, n>0
r_i(X) = r_i0 [1 + (X_c/(X+X_eps))^p],  r_i0≥0, X_eps>0, p>0
```

这些函数仅用于检验“下降速率、平衡、再吸湿”的结构行为，**不是棉或涤纶的已标定等温线**。未来应替换为有温度/吸脱附路径说明的数据表或拟合关系。计算所需 `X_b,n,r_i0,X_c,p` 全部进入来源登记，不能只给一组参数然后将结果命名为“棉衣实测”。

干燥子模型首版沿用 `0–50°C`、无冻结的研究范围，并对织物温度另行检查。原资料中的武汉 2024 年数据有 395 个小时环境温度不在该范围内，必须输出超域/暂停，不得裁成 0°C 后继续当作全年有效预测。雨情电子检测与低温供电也分别有自己的适用范围。

## 5. 如何与现有局部探头模型连接

现有短窗口模型没有 `X` 库存；未来可由慢模型提供 `a_w(X,T)`，但不能直接把局部腔体水汽曲线反演成整件水量。

若研究探头覆盖区域，应统一质量关系：

```text
V dρ_c/dt = A_cov J_cov + Q(ρ_a − ρ_c) + m_dot_wall
J_cov = [a_w ρ_sat(T_g) − ρ_c] / (r_a,c + r_i)
M_total = A_open J_open + A_cov J_cov
```

衣物的水量与潜热支出使用同一个 `M_total`。不能先按整件完全开放扣一次蒸发，又把探头覆盖区域再扣一次。新密度形式与原等温分压形式的转换，需要明确温度；若腔体温度明显变化，需增加腔体热平衡，不能默认为等温仍有效。

第一步实现分开验证：慢模型生成状态轨迹，短窗口适配器只在其温度/环境变化限制内产生观测。否则输出不适用。后续完整腔体热模型的闭合参数依旧未知，本轮没有解决该物理参数问题。

新增候选观测为衣物表面温度，可帮助观察蒸发冷却，但接触热阻、日晒和传感器自身扰动需建模。低成本光照读数只宜作日照趋势/遮挡指标：lux 不能使用一个固定系数无条件变成 W/m²。风速若没有本地传感器，只能作为不确定输入；不能把 2 m 或 10 m 高度的格点风直接当衣物缝隙处气流。

课程设计的观测层建议如下，新增传感器都先以模拟接口表示：

| 观测 | 候选获取方式 | 初版缺失时 |
|---|---|---|
| 环境温湿度 | 原环境探头，遮阳、通风、远离发热部件 | 停止依赖该时刻的有效预测 |
| 局部温湿度 | 原可移动探头，保留安装身份 | 只作环境驱动的宽范围外推，不能称观测已校正 |
| 衣物表面温度 | 研究小型接触温度元件或非接触方式的代价 | 以热平衡计算的区间估计代替，标明非实测 |
| 光照变化 | 光电观测或太阳能侧监测，需解释其响应与朝向 | 采用气象/遮挡情景，不把光照缺失填成夜晚 |
| 局部通风 | 有传感器时记录本地风；初版不强制增加风速仪 | 使用弱/中/强有效换热区间并保持不确定性 |
| 本地受水 | 独立暴露的电容润湿头，光学方案作对照 | 仅可提供预报风险，不能宣称具备本地突发雨检测 |

## 6. 面料不确定性与预测算法

### 6.1 不强制识别面料，也不宣称消除了面料影响

面料名称不包含全部厚度、织法、后整理、颜色和层数信息。2025 年开放论文提供不同成分/结构的样品厚度、面密度和干燥比较，可用于建立试样级先验；该文的恒温实验不是阳台整衣试验。[S01](references/T09-sources.md)

初版采用集合估计：为初始水量、厚度、材料函数、漏风、太阳吸收和通风设置多个允许假设，保留与观测相容的成员。用户选择标签只改变先验，不把其他可能性一刀切掉；“未知面料”是正常模式。

建议流程：

1. 安装后建立新批次，初始化参数与状态集合；低信息情况下保持较宽范围。
2. 用环境观测推进各成员的 `X,T`，通过显式观测模型计算预期局部温湿度/表面温度。
3. 根据传感器误差、时序和模型误差检查残差。超域、安装变化时暂停更新或重新初始化。
4. 只有在观测确实对某个参数敏感时才收缩其范围；参数间无法区分时保留共同区间。不能同时任意调整漏风、面料、初始水量和风速后声称“自动学会面料”。
5. 用至少“环境持续、日照下降/高湿、通风改善”三种未来情景前向计算；有预报时保存发布时间、有效时段、位置和数据年龄。
6. 各区首次达到显式目标的时刻取最慢者。对所有仍合理的成员给出时间包络；某些成员在时域内达不到目标，则上界为未知/超出时域。
7. 单点观测没有约束慢区时，结果标记局部或模型外推，不伪装成全衣测量。

若没有经过校准的概率分布，应称“情景范围”，不叫“95% 置信区间”。课程设计可在电脑上运行较大集合，STM32 移植再考虑查表、小规模集合和流式特征；不预先承诺所有估计计算都能放入 U031。

### 6.2 输出和授权分离

新增预测输出至少包含：`prediction_scope`、`computed_at`、`last_observation_at`、`model_version`、`parameter_source`、未来环境假设、`eta_lower/eta_upper`、`horizon`、超域/未知原因、`SYNTHETIC_UNCALIBRATED` 标记。

`eta=0` 只表示模型演示目标已满足，不能改变原来的 `collection_authorized=false`。原有 T04 研究状态和 T07 通知协议不应被偷偷赋予新含义；未来接入要新增版本与验证。

还存在一个无法凭算法消除的问题：初始水量、面积、漏风与内部阻力未知时，不同衣物可以给出相近局部曲线但具有不同剩余时间。集合估计用于表达这一不确定性，不是数学上解除不可辨识性。

## 7. 雨情：预警与本地证据分别处理

### 7.1 对用户提出的逻辑的判断

“白天变暗＋湿度高＋预报有雨”可以形成风险提示，不能直接确认当地正在下雨。光线降低可能来自遮挡，湿度高可能来自降温或雾露；即便接近饱和也不必发生降水。天气预报描述未来有效时段中的风险，不是衣架所在位置此刻的雨滴观测。[S05–S06](references/T09-sources.md)

也不能把阴天作为必要条件：夜间下雨、太阳雨和突然局地雨都可能绕过该条件。用当地太阳高度或日出日落区分正常夜晚，有助于避免“天黑=雨”，但不是检测雨的前置门。

### 7.2 建议的独立雨情分支

| 输出 | 证据和动作 | 限制 |
|---|---|---|
| `RAIN_RISK` | 有效预报/短临信息，或白天光照突降伴环境变化；提前提示 | 未经标定的融合分数不称概率，不确认下雨 |
| `LOCAL_WETTING` | 本地暴露表面出现新润湿，立即发本地受水风险事件 | 可能是雨、露、滴水或喷溅 |
| `RAIN_LIKELY` | 润湿增长与反复滴落/第二证据相容；提示疑似正在下雨 | 独立证据和阈值仍需验证 |
| `RAIN_SENSOR_UNKNOWN` | 探头失效、遮挡、长期湿滞留或未部署 | 不能显示“没有下雨” |

低成本首选研究涂覆电容式润湿表面，采用低占空比激励/读数，必要时增加干参考和比较器唤醒。它直接观测表面有水，但不能单独区分露水和降雨。METER 的电容叶面湿润传感器说明了凝结与雨水都会被感知；不能把该商品的精度和阈值移用到自制板。[S07](references/T09-sources.md)

光学雨滴可作为第二方案和对照。Hydreon RG-15 的厂家资料列出干燥无输出时约 110 μA、下雨时 2–4 mA，但它是独立完整传感器，体积、供电与成本不适合作为未经比较就选定的衣架部件，也不证明自制光学方案达到该指标。[S08](references/T09-sources.md)

雨头需要暴露在与衣物受雨风险相关的位置；屋檐/玻璃后的雨头没有滴水不能排除外面下雨。相反，屋檐滴水也可能造成非降雨触发。露点接近只能提供凝露解释，不能否决真实雨情。

建议在低功耗前端独立轮询/中断下研究秒级发现，雨事件立即唤醒通信，不等常规十几分钟的上报周期。实际延迟应分为采样等待、判断等待、Wi-Fi 建链、服务与手机延迟。不得以本地采样周期代替手机送达延迟。

### 7.3 与干燥模型、功耗及旧通知的关系

本地润湿优先提示，暂时撤销旧预测适用性；确认衣物实际受水后才给 `R_j` 赋水量。一个二值雨滴传感器不能测出衣物实际吸水多少；未知时扩大水量集合，不能编造降雨强度。

雨提醒不需要干燥标定授权，属于独立环境风险事件。但 T07 目前只允许研究复核/状态更新，因此新增雨事件、优先队列、过期和撤销策略需要单独接入任务，不能假称已完成。

## 8. 通信选择

```text
环境/局部探头、雨头
          ↓
STM32：本地采集、质量判断、研究状态、任务调度
          ↓ UART/SPI（候选）
无线模块：按需 Wi-Fi 联网
          ↓
家庭路由器 → 可达服务端 → 手机推送/状态查询
```

Wi-Fi 是设备连接家庭路由器的方式，云服务器不负责“建立本地 Wi-Fi”。同一局域网中，手机可经路由器访问设备或本地服务；手机离家后通常不能直接访问家庭私网地址。

| 方案 | 适用处 | 本项目取舍 |
|---|---|---|
| 局域网直连 | 同一网络、App 前台演示 | 课程设计可用；不能替代离家提醒 |
| 设备主动上传＋服务端转发 | 手机离家、事件保存/重试 | 默认产品方向；当前电脑模拟，不部署 |
| 互联网 P2P | 需处理信令、NAT/防火墙、在线状态 | 不作为初版默认，失败时还可能需要中继 |
| 低功耗本地无线＋常供电网关 | 多衣架或无线耗电占比很高时 | 可降低衣架负担，但增加网关成本与全系统能耗 |

ICE 使用 STUN/TURN 处理连接路径，直接路径不可达时可能经中继，且信令仍需另行解决。[S11](references/T09-sources.md) 因此“点对点”不等于必定无服务器，也不自动降低待机耗电。

端到端加密与点对点路由是不同概念。经过中继仍可加密到手机，但需要设备配对、密钥生命周期与兼容的消息路由设计；普通 HTTPS/TLS 只保护各段连接，不能直接称为设备到手机的端到端加密。本轮不新增未实现的加密承诺。

后续以短时 HTTPS 事件提交作为易演示候选，并与 MQTT 的实际重连/保持成本比较，不凭协议名称决定哪个省电。App 在后台接收要走适合目标手机平台的推送路径；手机厂商与网络条件尚未确定，不将某个服务视作中国所有手机都可用。

课程设计中，现有电脑可同时运行设备模拟器、服务和接收界面。用断网/延迟/重放情景演示逻辑，明确这是模拟链路，不为此租云服务器。

## 9. 省电与面积必须一起设计

建议原则：

- 低频采集环境、批量计算/上报；状态变化和雨情例外触发。
- 不维持无必要的 Wi-Fi 常连接。深度睡眠会断开无线，必须计入重新扫描、连接和认证的成本；Espressif 官方睡眠文档明确无线在深睡眠中断电。[S10](references/T09-sources.md)
- 原主动协议保持完整，仅在有机会改变判断且能量足够时执行；被动方案作省电基线，不能假设两者信息量相同。
- 关闭常亮指示灯，分时给传感器/执行器供电，核对稳压器、分压器、雨头前端的静态电流。
- 低储能时优先保留本地风险感知与必要状态；电量真的不足则明确离线/不可用，不能宣称所有功能永远不降级。
- 软件流式提取均值/斜率等特征，减少整段原始数据驻留；保留可重放/质量检查需要的最小信息。历史回收需要新协议，不能静默丢弃防重放历史。

本轮计算采用 [assumptions.json](../research/design_extension/assumptions.json) 中的未实测工作量：0.2 mW 总常开预算，每分钟 0.02 J 的被动采集/计算，Wi-Fi 0.6 W、一次正常 6 s 或超时 20 s；主动周期沿用 T05 的 4.38 J 假设。转换效率 85%，加 25% 裕量，向上取整到 0.01 Wh。它们是预算情景，不是新硬件实测或旧 T05 默认配置变更。

| 情景 | 主要工作量 | 电池侧预算 Wh/日 |
|---|---|---:|
| 被动参考 | 24 次正常联网，无主动换气 | 0.06 |
| 保留主动观察 | 24 次正常联网，36 个完整主动周期 | 0.13 |
| 弱网压力 | 48 次超时联网，36 个主动周期 | 0.33 |

雨头常开预算必须在以后用实际电路验证，连续雨中的额外计算和联网也可能超过这些工作量；本表未加入专用风速仪或常开网关。计算脚本不能证明这个耗电目标已经实现。

## 10. 太阳能板面积与电池

### 10.1 统一单位

```text
E_harvest = A_pv × H_POA × η_pv × k_harvest × f_site
A_required = E_day / (H_POA × η_pv × k_harvest × f_site)
```

`A_pv` 为有效电池片面积 m²，`H_POA` 为板平面一天辐照 Wh/m²；`η_pv` 为光电效率，`k_harvest` 包括本算例中到电池的电气/温度等综合折减，`f_site` 是额外现场受光因子。若将来已用包含相同损失的 PV 输出，不再重复乘相同损失。倾角和朝向已包含在 `H_POA`，不能再次按角度重复打折。

本轮面积情景取 `η_pv=20%`、`k_harvest=60%`、`f_site=50%`，均为明确设计假设。`f_site` 不是测得的玻璃透射率，实际遮挡常是随时间变化的，最终应进入逐小时模型。

| 有效电池片面积 | 20% 效率下理想 STC 功率 | 弱光 500 Wh/m²/日收能 | 极弱光 100 Wh/m²/日收能 |
|---|---:|---:|---:|
| 5×5 cm，25 cm² | 0.5 W | 0.075 Wh/日 | 0.015 Wh/日 |
| 5×10 cm，50 cm² | 1 W | 0.150 Wh/日 | 0.030 Wh/日 |
| 10×10 cm，100 cm² | 2 W | 0.300 Wh/日 | 0.060 Wh/日 |

这是有效面积算例，成品板还需边框、封装和无效区域。0.5/1/2 W 不是任意同尺寸廉价板的保证。以主动预算 0.13 Wh/日为例，5×10 cm 在上述弱光假设下有很小盈余，在极弱光假设下则入不敷出。因此初步比较 1 W 与 2 W 级可分体面板，不冻结采购；被动低耗方案可以研究更小尺寸。

七天无光的平均能量容量下界：

```text
C_nominal_Ah ≥ E_day × 7 / (3.7 V × 0.70)
```

三种工作量分别约 162、351、892 mAh。这里预算已在电池侧，不再除一次负载效率；这是容量算例，不含具体电池低温、老化、瞬时压降、实际截止点及恢复充满所需时间验证。

### 10.2 武汉朝向比较

已下载武汉示例坐标 `30.59°N,114.30°E` 的 PVGIS-ERA5 2023 年数据，每种姿态 8760 个小时。相对水平的倾角：0°为水平，90°为竖直；方位约定南为 0°、东为 -90°、西为 +90°。完整计算见 [生成表](../research/design_extension/results/summary.md)。[S13](references/T09-sources.md)

| 姿态 | 年平面辐照 kWh/m² | 日均 kWh/m² |
|---|---:|---:|
| 水平 | 1435.07 | 3.932 |
| 南向 30° | 1594.25 | 4.368 |
| 南向 60° | 1437.92 | 3.940 |
| 南向竖直 | 989.19 | 2.710 |
| 东向竖直 | 760.10 | 2.082 |
| 西向竖直 | 730.82 | 2.002 |

南向 30° 是本年、本数据源、六个候选中年总量最高的姿态，不是连续角度优化或普遍最佳。此数据只考虑其配置的地形地平线，不代表实际建筑遮挡、屋檐、玻璃和衣物位置。年均量不能用于保证最差连续阴天。

推荐结构方向是可调、可分体面板，主机和温湿度探头保持遮阳隔热。全国适用性应通过更换地点数据、朝向、遮挡序列及目标失服务率来计算，不用一组“武汉参数”覆盖全国。北向遮挡、长阴雨、低温和弱网应设为压力场景；没有太阳能输入时，任何有限面积也不能持续提供能量。

成本优化应比较“板面积＋电池＋电源管理＋结构＋可能的网关”整体，而不是只压缩 MCU。没有冻结器件和报价，本轮不提供虚构的总价。

### 10.3 峰值供电约束

日能量满足仍可能在 Wi-Fi 发射时掉电。ESP32-C3 官方资料列出某些射频模式的峰值电流可到 335 mA；这是规定条件下的芯片数据，不是整机连接平均值。[S10](references/T09-sources.md)

BQ25570 是低静态电流收能器件候选，但其集成输出能力不能直接假定能支撑上述射频峰值。需要独立核对电池侧电源路径、稳压器瞬态、储能与电流限制；不以“静态电流很低”作为最终选择理由。[S14](references/T09-sources.md)

## 11. STM32 体积和算力分工

ST 数据手册列出 U031 的 UFQFPN32 为 5×5 mm，WLCSP27 为 2.55×2.34 mm；这只是封装尺寸，PCB 还需供电、去耦、调试连接和其他器件。小封装通常增加焊接/布板难度，课程设计不应只追求最小封装。[S09](references/T09-sources.md)

原候选 U031 的 SRAM 为 12 KB，当前 C 验证记录中的输入加机器状态在主机 ABI 下为 20896 字节，尚未包含完整栈、无线缓冲和新预测器。主机 ABI 不是目标芯片的精确布局，但已经足以说明“当前原样肯定可装入 U031”没有依据。

建议先在电脑完成模型与参数集合，再做目标交叉编译和最大内存预算；通过流式计算、合理历史回收和任务分工降低内存，或据测算换用更大 SRAM 的 STM32。无线模块处理联网，服务/电脑运行较重的集合推演；本地仍保留雨情和基本状态，不依赖云端才能识别事件。

太阳能板、电池、天线净空和测量气路可能比 MCU 封装占更多空间，必须整机布局后才有可信尺寸。当前不新增未经布局验证的“整机只有几厘米”承诺。

## 12. 无硬件情况下的证据路线

本轮取得两套真实来源的公开环境数据，但它们都不是衣物实验：

- NASA POWER 2024 年武汉逐小时温度、RH、2 m 风、水平太阳能量和降水，每个字段 8784 条；原响应的太阳量单位为 **Wh/m²**。[S12](references/T09-sources.md)
- PVGIS-ERA5 2023 年六姿态逐小时平面辐照，每个姿态 8760 条，响应注明 **小时平均 W/m²**，乘一小时后积分。[S13](references/T09-sources.md)

原始响应、URL、来源单位和 SHA-256 已保存；两个年份分别分析，不能拼接成同一年同步观测。NASA 小时降水只能作天气背景，不能作为秒级突发雨检测的标签；未来预测评估也不能把实际未来天气当作当时已经知道的预报。

下一实现任务需完成：

1. 热湿模型的单位、守恒、平衡、蒸发冷却、吸湿、排液和零库存检查；至少两种步长及独立积分对照。
2. 普通区/慢区差异，未知/错选面料，甩干初值区间，风速与日照突然变化，雨后再湿和低温超域情景。
3. 观察器只能读取合成传感器输出，不读取真实参数、场景名或隐藏水量；保留同观测不同剩余时间的反例。
4. 比较固定时间、单湿度门限、被动差分、物理模型集合等基线；报告合成情景中的提前判断、区间覆盖、拒判、等待与能量，不能称实物准确率。
5. 用不同的参数族/未建模扰动生成挑战集，不只拿同一方程生成与拟合后宣称泛化。公开论文的小试样数据只在原条件下对照，记录图像数字化误差及独立留出。
6. 雨情单独测试夜雨、太阳雨、高湿无雨、阴影、凝露、喷溅、探头遮挡和预报过期，再与能量/通知接入。

课程设计可以交付数学推导、参数来源、公开天气驱动、合成传感器、状态/通知演示和资源预算。其结论应为“模型与算法在所列假设下通过检验”，不写成“已经证明真实衣物判干准确率”。

## 13. 对现有项目的影响

原始模型及通过记录保留，不重命名为完整干燥预测。新增研究应在独立目录实现，使用自己的配置、来源清单和输出。T04/T07 的无收衣授权边界不变；新增预测和雨事件在版本化接口中接入。

开发顺序调整为本轮 T09 设计补充 → T10 物理模型与条件时间算法 → T11 雨情/能量/通知集成 → T08 理论总评审 → 条件允许后 H01。当前只完成本轮定义的文献、方程、公开数据和预算工作，不自动执行后续实现任务。
