- 证据：[T01 协调验收](verification/T01-review.md)、[测量契约](MEASUREMENT-CONTRACT.md)。批次、重启和跨周期时间边界留给 T04。

## D10 — 优先单面气窗研究，背片保留为可拆对照

- 日期：2026-10-24。状态：候选方案，细化 D04，不冻结最终产品结构。
- 决定：优先用单面气窗腔体 C 研究受控条件，保留开放布点 O 作为被动对照；背片 B 作为 C 的可撤比较变量。
- 理由：C 更便于固定部分几何并拆分开窗、关窗、空白与装夹因素。共同参数包络没有提供三种实物的漏风范围或性能排名；背片还可能改变局部干燥并形成背侧储湿。
- 证据：[结构比较](PROBE-CONCEPTS.md) 和 [T02 协调审查](verification/T02-review.md)。两种协议中壁源替代和非唯一参数反例仍成立；调整时序只改变部分研究特征和状态。
- 继续条件：独立约束气路、材料历史、安装响应及覆盖干扰。实际范围、允许扰动和整件衣物参考由后续实验定义；不足时收窄为局部趋势研究，保持未确认，不以增加次数解除歧义。

## D12 — 用显式身份与时间域组织多周期证据

- 日期：2026-10-25。状态：当前工作决定，落实 D11 对 T04 的边界。
- 决定：新建独立 PC 状态机，继续调用已验收的原始观测判定器；以启动、批次、安装和周期身份隔离证据，完整配置身份覆盖协议、Gates 与状态机策略。换衣、开夹、配置改变、重启与当前域异常均不能保留原弱链；重复周期不增加计数。
- 理由：旧 EvidenceTracker 只累计判定标签，不能处理乱序、重放、重装与时间窗口。新层同时检查 start／finish 时间包络和单周期原始观测，但仍依赖可信调用方提供真实身份及样本时间关联。
- 证据：[状态机契约](STATE-MACHINE.md)、[T04 协调审查](verification/T04-review.md)。连续弱信号只触发研究复核标记，所有状态均无收衣授权。
- 范围：最大证据间隔限制前一弱周期结束后的闲置时间，不限制整条链年龄，不代表统计独立。PC 历史集合尚无容量上限；T06 必须另行验证有界存储、去重回收和掉电行为，不能直接照搬为长期运行的固件。
- 重新评估条件：T05 调度接入发现不合适的时间约束，或 T06 存储设计需要改变事件契约时，更新版本并重新验证；物理判干授权仍需 H01 独立标定。

## D13 — 节能对照同时记录服务缺口与证据连续性

- 日期：2026-10-25。状态：当前工作决定，落实 T05，沿用 D07／D12 的未标定边界。
- 决定：以当前完整协议和真实 StateMachine 接入秒级能量账本；测量预算完成、原始质量有效、研究复核和联网确认分别记录。低电量只限制任务机会，不修改配置或缩短协议；准入预留完整动作与退出能量，不借未来太阳能。
- 理由：旧五分钟占位原型无法说明实际测量是否有效；只比已耗电量会掩盖未服务请求。固定／按需对照必须保留共同外部请求分母、失败／删失等待和证据过期。
- 证据：[能量调度契约](ENERGY-SCHEDULING.md)、[T05 协调审查](verification/T05-review.md)。正常合成情景两策略同样服务全部请求，但 40 分钟按需触发使弱链反复过期；固定策略等待又受特设到达相位影响，不能据此选出普遍更优的产品策略。
- 边界：新增采集增量、启动与连接成本均未测；平均能量不证明瞬态供电。跨模拟重启保留额度与墙钟预留不是硬件持久化实现。T06 需处理有限内存和时间边界，实际供电、触发和判干仍待独立实测。
- 重新评估条件：实测负载／收能／触发分布或冻结协议改变时重新生成对照；不能通过放宽证据过期条件制造节能优势。

## D14 — 用明确的有界 C 配置验证移植边界

- 日期：2026-10-26。状态：当前实现决定，落实 T06；不冻结芯片或产品调度策略。
- 决定：把原始观测判定、多周期状态更新和必要能量原语移植为无驱动的 C99 核心，标识为 `T06-C99-BOUNDED-1`。完整测量协议经过校验后显式投影到整数秒能源接口，不截断。原 Python 与已验收结果继续保留为参考。
- 有界语义：固定样本、身份与历史容量，耗尽锁存故障并清证据；正常 boot／recover 不能清掉锁存。真正冷初始化需要外部保证全新可信身份。先验证安全的有限输入行为，长期回收、可信序号和持久化尚未实现，不能将此原型当作可长期运行的固件。
- 数值选择：保留研究门限，用固定整数累加和一次舍入解决已见的均值临界分类差异；门限分类仍精确比较，数值容差不豁免状态不一致。Python 转 C 计数须先检查类型与范围，防止超大整数取模成合法计数。
- 已知不同域：C 明确限制身份为最多 32 ASCII 字节、时间／样本／计数上限、无线跨日跨度；能量启动还要求实际支付成功，拒绝微小能量域内 epsilon 造成的未付费启动。内部类型规范化摘要不替代原始 JSON 字节级冲突检测。
- 证据与限制：[C 接口](CORE-INTERFACE.md)、[T06 协调审查](verification/T06-review.md)。主机对象、结构和栈测算不等于目标 STM32 的 RAM／实时性验证；默认观测加状态已超过 20 KiB 主机内存，未来需压缩或流式设计及目标工具链复验。
- 重新评估条件：改变容量、历史回收方式、传输契约、数学库、编译器或目标 MCU 时重新生成并运行相应对照；物理收衣授权仍需独立实测标定。

## D15 — 研究提醒使用证据时间与最新状态隔离

- 日期：2026-10-27。状态：T07 当前实现决定；不等于未来产品收衣授权。
- 决定：实际运行 T04 原始观测状态机，只传递研究复核提醒；持久生产者／启动／事件序号区分身份，重连原子同步最新 head 后处理积压。原始证据时间与 TTL 不随 tick 或重发延长，要求配置与已应用配置分开。
- 理由：旧模拟授权路径无法证明正式状态接入；只做重试会重复或复活旧提示，保存确认与手机收到也不是同一事实。满队列仍预留撤销 head，锁存停止而不继续传播旧状态；重复旧 ACK 无操作且不能释放未确认的新消息。
- 证据：[通知契约](NOTIFICATION-CONTRACT.md)、[T07 协调审查](verification/T07-review.md)、[主收据](verification/notification-tests.json)。所有通知继续 `collection_authorized=false`。
- 限制：服务端无法知道尚未上报的离线变化；SQLite 进程恢复不是 Flash 掉电保证，时间误差及 TTL 仍是假设。真实推送、认证、无线能量协同和长期回收尚未实现。
- 重新评估条件：T08 确定最小实验／产品状态边界，或未来独立实测标定、真实设备与通知接入改变时钟、容量和确认语义时，版本化更新并重新验证。
