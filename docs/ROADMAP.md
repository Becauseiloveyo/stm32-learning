# 开发步骤与任务验收

本文件定义工作，不记录动态进度。当前任务和完成情况只读 [STATUS.json](STATUS.json)。用户新指令改变范围时，先更新约束与相关任务卡，再推进实现。

用户已授权分工对话协作。具体文件所有权、预研范围和交接见 [TEAM.md](TEAM.md)。分工对话不直接更新主状态；后续阶段可以先做独立预研，但正式验收仍遵守以下依赖。

## 每次工作的固定流程

1. **恢复**：读取项目约束、状态，运行 `tools/project_status.py`。只加载当前任务列出的输入，缺信息时再查相关决策或来源。
2. **界定**：确认一个任务的输入、输出与验收；将状态设为 `in_progress`。记录当前不处理的相邻任务，防止实现时不断扩张。
3. **开发**：小步修改；参数有单位和来源标签；改变假设时说明对旧结论的影响。
4. **检查**：完成任务指定的计算、测试或文档核对。失败就保留失败记录并继续修复；不能用文字描述替代尚未运行的验证。
5. **交接**：在 STATUS 中记录状态、改动文件、实际命令、结论边界、未解决问题和明确下一动作。必要时追加决策记录。选择依赖已完成的下一任务。

单次对话默认完成一个有明确验收边界的任务；若上下文不足，在一个可恢复的小步骤处保存状态。换对话后沿 `resume_action` 继续，不根据旧聊天重新猜测进度。仅设计步骤的请求不自动执行后续任务。

验证过期不是永久障碍：若实现刚发生改变，重新生成对应证据并检查即可；若用户只修改文字，则无需为了更新日期重跑无关模型测试。

## T00 — 建立项目入口与交接机制

- **目的**：把用户要求、技术假设、实现状态与后续任务分开，使工作可从文件恢复。
- **输入**：现有项目文件、用户已确认的预算与使用场景。
- **产出**：README、AGENTS、PROJECT、STATUS、DECISIONS、本路线图和状态检查工具。
- **验收**：入口指向有效文件；状态依赖一致；现有仿真源指纹匹配；模型测试具有当前源码的可核对记录；有且只有一个明确的下一任务。
- **边界**：不修改物理模型和默认阈值，不部署或购买任何东西。

## T01 — 固定测量协议，统一参数入口

- **依赖**：T00。
- **输入**：`theory/model.py`、`theory/run_simulation.py`、`theory/test_model.py`、`theory/README.md` 第 5–6 节。
- **问题**：目前阶段时长在模型参数中，而有效性检查里的 80 秒、2.5 秒、特征窗口仍是硬编码；修改采样方案可能造成规则不一致。
- **步骤**：盘点所有参数；区分物理假设、测量协议、算法阈值和证据标签；给观测记录制定字段、单位、缺失值与版本规则；让模拟器和判定器读取同一协议定义。
- **产出**：`docs/MEASUREMENT-CONTRACT.md`；明确的协议／参数配置入口；修改后的模型接口、测试和生成清单。采用配置文件还是类型结构由实现决定，不能保留两套独立可编辑默认值。
- **验收**：默认协议的可解释行为与基线一致，改变之处有说明；至少两种采样协议通过；缺阶段、缺数据、非法单位／范围得到明确结果；来源清单覆盖新增配置；情景名称或真值不参与判定。
- **边界**：不以本任务标定“可收衣”阈值，不扩大物理模型。
- **交接重点**：最终配置位置、接口版本、采样协议变更后的必跑检查。

## T02 — 比较气路结构与可辨识性约束

- **依赖**：T01。
- **输入**：T01 协议文档、`theory/README.md` 第 2–4 节、`hanger-drying-architecture.md` 第 3–4 节。
- **步骤**：比较开放布点、带气窗的单面腔体、增加背侧挡风的腔体三个概念；为各结构画气路图，列出可控量、可观察量和仍未知的量；把漏风与壁源区间代入模型。
- **产出**：`docs/PROBE-CONCEPTS.md`，结构参数表、可复现的对比情景和选择理由。
- **验收**：每种结构说明其漏风假设及对布料干燥的可能干扰；至少包含一个不利反例；不能因降低所有假设漏风量就宣称抗风性能提高；结论明确为理论候选。
- **停止／调整条件**：如果所有候选都无法合理约束关键歧义，记录需要的独立补充观测或缩小的应用范围，保留已有反例，而不是强行选“最优”。

## T03 — 分析模型失配、误差与适用范围

- **依赖**：T02。
- **输入**：T02 对比、现有不确定度推导、模型与传感器原始资料。
- **步骤**：加入温差／响应时间失配、偏置与缓变、壁源变化的敏感性分析；对需要扩展的物理关系查原始文献，注明参数是来源值、假设区间还是未知。
- **产出**：`docs/MODEL-VALIDITY.md`，受支持的模型扩展、误差预算与不适用条件，及相应情景／检查。
- **验收**：新增状态量满足明确的质量或热量关系；极限情况能退回已有模型；误差不被重复计算；没有真实数据时不输出真实面料的准确率或干燥时间。缺乏依据的扩展允许明确暂缓，但要说明不能支持的结论和未来最小实验。
- **边界**：不为了得到完整曲线而捏造真实织物参数。

## T04 — 多周期证据状态机

- **依赖**：T03。
- **输入**：测量协议、模型适用范围、现有 EvidenceTracker、总体架构的异常处理要求。
- **步骤**：定义安装／稳定／测量／待确认／异常等状态与转换；记录批次 ID、时间和配置版本；处理连续证据、开夹、缺数、重启与批次切换。
- **产出**：`docs/STATE-MACHINE.md`、可在电脑运行的状态机与重放测试。
- **验收**：旧衣物的证据不会带入新批次；无效窗口不能增加确认次数；时间重复、跳变和重启不会制造完成事件；未经标定的研究模式始终保留未确认状态。
- **边界**：本任务完善证据链，不把合成场景训练出来的阈值当实物标定。

## T05 — 将测量调度接入能量模型

- **依赖**：T04。
- **输入**：状态机、`analysis/energy_budget.py`、`power-notification-design.md` 的能量与低电量章节。
- **步骤**：按时间记录测量、气窗、联网、充电和储能变化；比较固定复核与按需复核；加入连续阴天、弱网重试和低电量恢复场景。
- **产出**：`docs/ENERGY-SCHEDULING.md`、可复现时间序列模拟、预算和行为对照。
- **验收**：消耗、储能、弃能与供能缺口守恒；电池不足不继续假装动作已完成；低电量只改变任务机会，不放宽判定阈值；区分日能量模型与尚未实测的瞬时供电能力；比较等待和无结果比例，不只比较省电。
- **边界**：不把拟定太阳能功率或容量冻结成采购规格。

## T06 — 可在电脑验证的纯 C 核心

- **依赖**：T05。
- **输入**：已固定的协议、状态机、调度接口与 Python 参考实现。
- **步骤**：在独立于硬件驱动的 C 模块中实现必要计算与状态更新；定义固定单位、错误码、时间处理和内存边界；用同一组回放向量对比参考实现。
- **产出**：`firmware/core/`、主机编译／运行入口、`docs/CORE-INTERFACE.md`。
- **验收**：在可用的本机编译器下实际编译运行；数值误差有容差依据；关键状态与 Python 一致；无效值和时间边界行为一致；内存需求有测算。没有编译环境时记录缺口，不能把未编译代码标记为已验证。
- **边界**：不连接或刷写设备，不声称已具备完整 STM32 固件。

## T07 — 离线验证远程提醒协议

- **依赖**：T06。
- **输入**：状态和事件接口、`power-notification-design.md` 的通知流程。
- **步骤**：用本地模拟端实现事件生成、持久队列语义、服务端确认、重发去重、旧事件失效和配置版本；设计 App 需要显示的状态及时间字段。
- **产出**：`docs/NOTIFICATION-CONTRACT.md`、本地消息链路模拟与失败情景检查。
- **验收**：断网后状态改变不会补发过时收衣通知；重复提交不重复提醒；重启不重复使用事件 ID；确认的含义区分保存、推送和用户已读；未标定研究事件不会冒充真实收衣结果。
- **边界**：不部署服务器、不申请付费服务；不把离线通过当成手机后台送达率验证。

## T08 — 理论阶段评审与未来验证包

- **依赖**：T07。
- **输入**：T01–T07 的产出；PROJECT 中 R01–R08；未来硬件实验清单。
- **步骤**：将用户要求逐项映射到实现、理论证据、未解决问题和最小实验；统一文档中的版本、术语和参数引用；评估主动采样是否仍值得作为候选。
- **产出**：`docs/THEORY-REVIEW.md` 和更新后的最小硬件验证计划。
- **验收**：每项用户要求有状态和证据路径；任何准确率、功耗、续航、创新性说法都能追溯其来源和限制；未解决问题没有藏在“已完成”里；给出预算允许后最少需要测什么。
- **边界**：理论评审通过只表示准备充分，不能把 H01 的实测验收提前宣布完成。

## H01 — 后续硬件验证阶段

- **依赖**：T08，且用户后续明确改变当前预算／实施条件。
- **输入**：理论评审与 `first-validation-plan.md`。
- **产出**：真实测量、参数替换、独立参考标注、冻结参数后的留出批次结果。
- **验收**：按照硬件计划验证信号、误报／延迟／无结果比例、结构扰动、峰值供电和实际收能；随后决定具体产品实现。
- **当前处理**：保留入口，不在零采购阶段推进。

## 更新进度的最小格式

在 STATUS 的 `last_handoff` 中填写：任务 ID、实际完成内容、变更文件、运行过的命令、证据限制和下一条可执行动作。失败也要写具体重现条件；不要只写“继续优化”“后续完善”。

在 `open_issues` 中保留未解决问题的 ID、影响和对应任务。解决后注明证据再移除；不要因换聊天而把问题丢失。
