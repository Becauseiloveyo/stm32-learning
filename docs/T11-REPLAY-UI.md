# 晾衣观察室

下载或双击[单文件中文回放](demo/hanger.html)。回放数据、界面样式和交互都在这个 HTML 文件中，可以断网使用。在 GitHub 文件页面使用 **Download raw file** 下载后打开。桌面和手机宽度的显示见[桌面截图](../output/playwright/t11-p3/desktop.png)和[窄屏截图](../output/playwright/t11-p3/mobile.png)。

## 先看一次受水提醒

页面默认打开“受水 · 断网后重连”的第 62 秒。左侧衣架已经发现探头受水，撤销原预测；右侧模拟接收端最后一次在第 26 秒收到数据，仍能看到当时的条件估计。展开“查看远端依据”，能看到那个版本的中央接触、探头、预报和未来环境假设。

拖动关键帧滑块，或按左右按钮逐帧查看。显示时刻采用分、秒，两帧之间可以相隔不同秒数。第 100 秒起，远端按证据原有效期移除旧估计。第 148 秒，重连成功，服务保存和模拟接收都显示 02:28。历史待确认数与最新状态是否到达分别显示，因为一个成功的连接可以携带最新状态，同时只确认一条历史。

“断网期间换衣”可以看为什么联网前后的显示不同。“预报未报风险 · 探头受水”把两种证据放在一起。“确认丢失后重发”中第 68 秒新增一次提示，第 148 秒再收到同一提醒键时新增数为零。受水这一判断不提供降雨成因或衣物含水量。

## 数据如何到达界面

生成器在独立临时库中逐秒运行已验收的 P2 Rig，通过衣架持久状态、服务当前版本、模拟接收端当前版本、当秒日志和电池账构造帧。接收端只使用已分发的版本，并按查看时刻重新判断每项证据是否仍有效。回放允许读者同时看到两端，色块上的版本对照属于观察者视角；离线手机不能据此知道现场刚刚发生了什么。

每个有效时间估计都注明分析时刻、证据期限和 M6 使用的未来条件。显示值是分析时刻到模型首次网格检出目标的有限候选上界；切换帧时不会自行倒计时。缺测、失配、身份改变或故障会撤掉不再适用的数值。中央未接触时只显示设备状态。环境、设备和网络均为合成输入，真实手机送达始终未知。

## 界面参考

- 事件记录把同一帧已经发生的动作合并在一个时间节点，倒序显示最近五次变化。参考 [Ant Design 时间线示例](https://ant.design/components/timeline/)。
- 收据过期、热干扰、远端滞后等解释与受影响的读数相邻，切换帧前可以一直阅读。参考 [IBM Carbon 的内联通知](https://www.carbondesignsystem.com/building-blocks/core/components/notification/guidelines)。
- 标签直接写明版本一致或滞后，操作放在选择框、滑块和翻帧按钮上。参考 [GOV.UK 状态标签](https://design-system.service.gov.uk/components/tag/)。

## 复现

```sh
python -B -X utf8 -m research.integration_t11.p3.build_panel
python -B -X utf8 tools/check_hanger_panel.py --check-receipt
```

第一条从模型生成同一份页面并逐字节比较。第二条核对验收时绑定的文件与上游收据。完整重跑使用 `python -B -X utf8 tools/check_hanger_panel.py`，需要本机 Chrome/Edge、可用的 Playwright CLI 或已缓存的 npm 包。浏览器检查仅使用临时回环地址，另以本地文件方式验证首次打开。普通浏览这个页面无需运行上述命令。
