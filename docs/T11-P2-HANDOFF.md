# T11 P2 预备交接：完整动作与持久链路

2026-11-02。此文件准备后续工作，不代表 P2 已启动。先接受 P1 的真实接口和独立收据，再冻结输入、明确所有权和派发；不得直接修改已接受包。

## 需要解决的真实接口差异

1. **T12 能量不是动作调度。** T12 是零时长增量能量脉冲；T05 是基线/冲洗/恢复共 140 秒的完整动作，包含开关边界和取消安全退出。P2 需复用 T05 `measurement_components` / `required_battery_wh` 或逐项等价核对，并保留动作占用时间；预留是准入条件，不是提前扣一次、执行再扣一次。
2. **工作负载必须选定一套。** T12 正常无线示例为 0.6 W×8 秒，T05 成功为 6 秒、最坏超时20秒。两者是不同未测情景。P2 在新配置显式选定并登记，不把 4.8 J 脉冲叠加到已积分的无线功耗。T12 0.2 mW 基线与 T05 1 mW 加杂项也不能重复收取；明确所选基线包含与不包含什么。
3. **无光伏边界在新层定义。** 用 T12 可用容量公式、充电输入侧/效率和半开区间约定；外接充电只在已发生区间供能。保持旧 `Solar` 类与收据原字节，不把新人工充电偷偷作为太阳能变量的意义变化。若复用底层积分，适配层必须说明同一数学供能为何不等于沿用光伏产品。
4. **观测模型不能混接。** T05/T04 的旧短周期观测属于 T01 模型，M6 使用 M5 同一动态状态及 RH 分数等约定。不得把旧 assessment 或弱证据次数当作 M6 水量/新样本。完整动作完成、采样质量与 M6 请求可用性分别判断；新合成采集只能由独立生产端按已声明模型生成，不能从隐藏衣物含水真值直接生成结论。
5. **旧消息类型不是扩展接口。** T07 `Event` 仅允许 T04 研究复核和状态更新，服务检查真实上游投影；不能把雨事件伪装成 T04 `AWAITING_RECHECK`。新版本需清楚说明实际复用的存储/事务帮助函数、扩展的消息验证与仅借鉴的语义，旧链路仍可独立恢复。
6. **通知意图还不是队列。** P1 的状态/意图需要持久化后才能上传；保留最新失效 head 的独立槽，满队列时不能只留下旧好消息。重试同一事件不延长观测时间/TTL，旧 ACK 不删除新域数据。新域、重启、断网中的未上报变化不能靠服务端猜测。

## 优先级与可用性

先明确同刻处理顺序、已开始动作能否取消、紧急本地受水与普通预测上报次序。优先级不等于有电保证，也不证明手机实时送达。雨头采样/唤醒/判断/排队/建链/保存/模拟接收分别记时间与已付成本；不提供未实现的手机延迟。

充电中热干扰和拔线后的恢复时长仍未知；旧证据不能随充电结束自动恢复。没有充电口受水检测，不能用雨头状态冒充端口湿度。无太阳能、无人充电、拔线中止、满电弃充、低电量拒绝、恢复、未来充电不可借用均需反例。

## 验收方向

独立解析核对能量账、全过程最坏预留、效率只用一次；中途取消已用功耗不能抹掉。断网恢复、同ID重发、迟到ACK、旧预测撤销、时效边界、满队列安全head、进程中断恢复必须走实际本地持久代码。新层不扩展真实认证或部署，不把 SQLite 或电脑内存当 STM32 证明。

## P1 已接受的接口入口

版本 `t11-p1-v1`，见 [事件契约](T11-EVENT-CONTRACT.md)、[独立审查](verification/T11-P1-review.md) 和 [收据](verification/T11-P1-tests.json)。开始 P2 时先运行 `python -B -X utf8 tools/check_integration_events.py --check-receipt`，再冻结实际使用来源。

实际入口为 `research.integration_t11.p1.controller.Controller(device,boot,batch,installation)`、`event_id(domain,seq)`、`apply(event,decision_s)`。示例在 `research/integration_t11/p1/results/events.json`，结果在 `snapshots.json`。JSON 中 M6 tuple 会序列化为数组，按公共 JSON 表示传输。

P1 拒绝发生或接收时间早于上次判断的新事件，不能直接充当支持乱序的网络服务；只保存最新撤销与内存高水位，不等于持久多事件 outbox。P2 必须在明确的端侧/服务侧边界适配这些限制，不能重新调用晚到采集事件并假设通过。`snapshot()` 不自行读当前时间，过期处理需要 tick/判断时间。两包内 null 样本能得到当前未知；不足两个包仍为拒绝，采集缺失须明确传 unknown/fault，不靠未执行预测来保持旧结果。

每个新版本预测有自己的键；撤销引用旧键。连续湿提醒的键属于同一湿事件链，后续新样本可延长该链的当前证据，但不能把不可变 event ID 的内容改写；notice 去重与 event 保存须分开。P1 优先级只是意图顺序，尚未决定能源在途抢占。最终 T11 还需 P3 界面与全矩阵验收，才可转 T08。
