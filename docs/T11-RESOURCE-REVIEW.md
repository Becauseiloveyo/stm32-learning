# T11 MCU 资源与回收估算

2026-11-03；设计上界示例，不是已实现格式，也不是器件选型或实测。P2 的 SQLite 及 Python 对象不得作为 MCU 字节数。P2 默认历史队列 32 条、最新状态独立；可靠性依赖单写者、可信身份和单调时钟。M6 当前在电脑运行，不计作设备代码。

## 可复算的候选编码

以下均为字节，固定宽度、显式序列化，无 C 结构体 padding；ID 采用 16 字节、必须有可信唯一性管理，不得截断现有 32 字符身份。计数上限是设计假设，超出拒绝并保持安全状态。64 位整数须验证非负及范围，时间统一整数秒（预测小数需另行定义精度、溢出及保守舍入）。

| 项 | 候选字段和字节 | 小计 |
|---|---|---:|
| 历史记录 | 版本/类型/标志 4，设备/启动/批次/安装 ID 4×16，序号 8，事件/到期时间 2×8，负载 28，CRC 4，提交标志 4 | 128 |
| 最新状态 | 版本/标志 4，四个 ID 64，序号 8，接触/热/湿/预报/预测及原因 12，分析/有效期/剩余等时间 5×8，条件和参数摘要 64，保留扩展 56，CRC/提交 8 | 256 |
| 元数据 | 版本/队列头尾/数量/淘汰计数 24，序号水位/退避/时钟 32，ACK 摘要 32，电量额度及恢复状态 32，CRC/提交及扩展 8 | 128 |

条件摘要不可代替服务端需要的完整条件；28 字节负载若不能表示所有事件必须拒绝或重新设计，不能截断。掉电恢复必须保留撤销、未知/失效状态、完整身份域、序号、到期、重试、淘汰统计和与记录绑定的 ACK；CRC 只检测错误而非认证。状态与历史及元数据必须原子一致，重启先持久化新 boot 的安全状态再发送。

假设最多 32 条历史：逻辑有效集 `32×128+256+128=4480 B`。若采用两个完整快照银行，每银行再留 64 B 世代头、CRC 和提交标志，最低 `2×(4480+64)=9088 B`，再按实际擦除块向上取整：`2×ceil(4544/E)×E`，E 为擦除块大小（字节）。这仅容量下界：实际还需磨损均衡、备用坏块、写入对齐、原子提交和迁移空间；目标介质及写入粒度未知，不能宣称可用。先写非活动银行、校验、最后原子提交，再回收旧银行；任一阶段断电只能恢复完整旧版或新版。这个方案每次完整复制，写放大严重，仅用于保守容量示例，不是推荐实现。

RAM 若全驻留历史及状态/元数据需 4480 B，另两个 128 B 编解码/发送缓冲合计 4736 B；若采用流式读取，可把历史常驻降为一条，工作集示例 `128+256+128+256=768 B`，仍须加实际网络缓冲和驱动。两者都是附加设计预算，不能同时相加，也未包含栈。T06 主机 ABI 已测 `hs_machine=9616 B`、默认 141×80=11280 B 输入，总计 20896 B；512×80=40960 B，连状态共 50576 B。简单相加全驻留示例分别为 25632 B 和 55312 B，前提是生命周期重叠且 ABI 相同；目标 ABI、对齐、栈、配置、输出、通信、RTOS、中断及库均未知。[C 基线](CORE-INTERFACE.md) 指出 64 事件等固定上限耗尽锁存，不能靠清历史假装长期运行。须目标编译 map、最大嵌套调用栈与中断高水位验证。

## 耐久与回收

完整双银行示例假设每次提交写一个银行且两银行均匀轮换；每日 N 次提交、每块额定擦写寿命 L 次时，理想寿命约 `2L/N` 天。例如纯示例 L=10000、N=1440（每分钟一次），约 13.9 天；无真实器件额定值和写入分布，不能当预测。需计入重试、状态变化、掉电、温度降额、放大与保留期；测量最坏写入率后选择日志、分段磨损均衡及留量。

回收只能在持久化水位和撤销后，确认旧记录既不可能改变当前状态、也不再需投递/去重；超时、满队列淘汰必须保留计数及当前安全 head，迟到 ACK 不可删新记录。服务历史须按设备/启动域与序号保存水位及未过期状态；提示去重键至少覆盖完整身份域和业务事件，保留到重试及迟到窗口均结束，并有可信时间/纪元；窗口无法证明时拒绝旧域或保留墓碑。端侧样本仅在计算完成或安全撤销、无待传/重试引用且到期后可回收，丢失条件要使预测 unresolved。窗口、容量、跨设备替换和长期数据库清理均未实现或验证，不能把这一设计当作现有 GC。
