# T11 P3 交接：把联动结果显示出来

下一包以 [P1 审查](verification/T11-P1-review.md)、[P2 说明](T11-P2-TRANSPORT.md)、[P2 审查](verification/T11-P2-review.md)、[T11 三包计划](T11-INTEGRATION-PLAN.md) 和 ROADMAP 的 T11 验收段为输入。开始时先运行 `python -B -X utf8 tools/check_integration_power_transport.py --check-receipt`，再冻结界面实际消费的字段和结果。无需购置设备、部署云服务或连接手机。

1. 用一次真实离线回放的状态生成一个可打开的中文最小界面。分开显示中央接触是否有效、干燥预测的分析时刻与条件、天气预报风险、本地受水、最近一次同步和失效原因。缺上界、失配、已过期、重启或换衣时，旧的剩余时间必须退出当前展示。不同位置的干燥程度仍可能不同。
2. 让读者能区分衣架已发现、待发送、服务已保存、模拟端已接收和手机送达未知。离线阶段按远端实际已知的快照显示，加上证据时刻或最后同步时间。若需要为界面扩展数据，优先在新层收集真实 P1/P2 输出，避免改动已验收结果字节或手填理想状态。
3. 把 ROADMAP T11 的每项验收条件对应到可重放场景与界面断言。包括有/无有效预报、本地湿与预报不一致、无接触、迟到、旧域、设备重启、低电、撤销、确认丢失、满队列和充电热干扰。验证成功情景时也核对失效后的下一帧。
4. 分开估算 MCU 持久队列与 RAM 的字节数，列出必须保留的失效状态、序号和排队元数据。评估服务历史、提示去重键和端侧样本回收条件；资源结论需说明序列化、样本上限及写入耐久假设。电脑 SQLite 文件或 Python 对象大小不能直接当 MCU 需求。
5. 独立复核后记录界面入口、复现命令、适用范围、未满足项和源码绑定收据。T11 总体验收通过后再转 T08。衣物已干的真实准确率、无线实耗、手机推送与充电口实物验证继续留给后续有设备阶段。
