# 项目详细功能说明

## 1. 产品定位与使用过程

面向家庭阳台，将一个小型监测装置安装在衣架上，通过环境参考探头和衣物附近的局部探头观察干燥相关变化。STM32 负责采集、测量过程控制和状态处理；未来通过家庭 Wi-Fi 将有效状态上传到服务端，再向离家的用户发送手机提醒。供电方向为低功耗电池运行与人工充电，不含光伏收能。

预期使用过程是：

1. 用户把衣服挂上，将局部探头固定在需要重点检查的位置，开始一轮新的监测。
2. 设备等待安装后的观察条件，按当前供电情况安排测量。
3. 采集环境与局部温湿度；如果保留主动采样方案，再执行短时换气与恢复观察。
4. 检查数据质量，形成当前研究状态，并结合后续有效周期继续观察。
5. 未来完成独立实物标定后，在已验证的使用范围内生成“建议检查收取”的提醒；手机在家外也可通过网络接收。
6. 换衣、重新安装、异常或重启后，结束旧证据链，重新开始观察。

**当前阶段仅在电脑上开发与验证模型和软件。没有已完成的实物设备、可部署固件、手机 App 或真实云推送；当前所有测量情景均为未标定合成数据，不能触发真实收衣建议。**

## 2. 衣架安装与可移动局部监测

**功能目标：** 装置随衣架使用，尽量减少用户额外操作，并允许把测量点放到更值得检查的位置。

- 主体安装在衣架上，容纳控制、储能和通信部分；具体尺寸、固定方式及防护结构尚未确定。
- 环境参考探头放在通风、遮蔽直射和远离设备热源的位置，提供当时的环境温湿度。
- 局部探头通过短连接线移动，可研究布置在袖口、接缝、腰部或口袋等位置附近；这些是候选测点，不是已证明适用于所有衣物的安装规则。
- 当前优先研究单面气窗腔体，保留开放布点作被动对照，可拆背片用于比较结构影响；最终是否采用腔体、背片和主动换气，需要实验决定。

**范围边界：** 一个局部探头只能支持所测位置附近的结论。不能把衣架顶部的读数直接解释为整件衣服、所有口袋或整排衣物都已干；多点、多衣物系统不属于当前已经确认的基本实现。

依据：[探头结构比较](PROBE-CONCEPTS.md)、[总体架构背景](../hanger-drying-architecture.md)。

防水为新增明确要求：主机/电池防护区与测湿透气区分开，润湿感应面独立暴露；检查接缝、线缆、充电口、冷凝及雨后恢复。不能用完全封闭的壳封住温湿度气口，也不能把器件的防护等级当整机等级。见 [防水设计与验证矩阵](WATERPROOFING-DESIGN.md)，当前无实物防水通过证据。

## 3. 环境与局部温湿度联合采集

**功能目标：** 同时知道“周围空气怎样变化”和“衣物附近空气怎样变化”。

- 采集两路温度与相对湿度，并记录相应采样时刻。
- 按测量协议检查数据是否完整、有效，阶段是否匹配，是否发生已知安装事件。
- 将温度与相对湿度一起用于水汽分压等特征计算，研究局部与环境的差值及其变化，避免仅用一个环境相对湿度门限判断衣物。
- 为后续判断保留原始观测和判定原因，便于追溯异常来源。

局部探头直接测的是空气状态，不能把它的相对湿度读数写成“衣物含水率”。温度补偿也不能自动消除装壳响应差异、漏风、太阳辐射或传感器偏差。

**现有证据：** 已有原始观测契约、特征计算、质量检查和电脑上的 C/Python 对照；没有真实传感器采集数据。

依据：[测量契约](MEASUREMENT-CONTRACT.md)、[模型适用性](MODEL-VALIDITY.md)。

## 4. 短时主动采样与恢复观察（候选功能）

**功能目标：** 在可控制的测量过程中观察信号变化，研究能否比单次静态读数提供更有用的信息。

候选流程为“记录基线 → 短时换气 → 停止换气并观察恢复”。如果局部仍有水汽来源，换气后的变化可能提供附加信息；但壁面放湿、漏风和温度变化也可能产生相似现象，必须比较和排除。

这一过程服务于测量，不承担烘干衣物的功能。风机、气窗及其结构都未定型。只有后续证明附加信息值得增加的体积、耗电和维护成本，才保留主动方案；目前不能宣称它比被动方案更准确。

**现有证据：** 已有短窗口模型、协议比较和合成场景分析；不模拟整件衣物数小时的完整干燥过程，也没有实际气路性能证据。

## 5. 多周期观察与状态管理

**功能目标：** 保留一次测量的上下文，避免用偶然变化或旧数据直接作出结论。

| 当前研究输出 | 对用户解释时的含义 | 不能据此推出 |
|---|---|---|
| 水汽来源明显 | 当前观察存在明显水汽信号，需要继续研究或观察 | 水汽一定来自衣物，或整件衣物一定很湿 |
| 弱信号未确认 | 当前信号弱，需要后续观察 | 衣物已经干燥 |
| 条件不明／输入异常 | 现有条件或数据不足以判断 | 默认当作干燥 |
| 需要独立复核 | 达到当前研究规则，应使用独立参考检查 | 已干、收衣授权或某个置信百分比 |

软件同时管理等待安装、安装后等待、可测量、测量中、等待复测和故障等过程状态。弱信号只能在相同批次、安装、启动和配置条件下按规则累计；重复消息不能增加有效次数。

**未来产品目标：** 在独立实测、参数冻结和留出批次验证后，定义适用于指定材料、测点和环境范围的提醒规则。当前没有这个已标定分支，全部 `collection_authorized=false`。

依据：[多周期状态机](STATE-MACHINE.md)。

## 6. 安装变化、拉动与异常处理

**功能目标：** 当测量条件发生已知变化时，不继续沿用旧结论。

- 换衣、开夹、重新夹取或变更测点：建立新的安装或批次身份，清空旧证据，重新等待与采样。
- 测量中断、数据不全、时间异常或当前配置不一致：按规则拒绝记录或进入故障处理，不能补算成一个成功周期。
- 设备重启：进入新的启动身份，不把旧周期当作本次启动的新证据。
- 过期、重复和迟到数据：区分处理，避免重复计数或覆盖当前状态。

风吹和拉动的处理需要分两层理解：软件已经能处理控制器报告的开夹、安装变化等事件，以及观测中可发现的异常；实际如何检测夹具变化、风扰、滑移或漏风仍需结构和采集层设计。**当前没有实际拉动或风速检测硬件，也不能保证发现所有扰动。**

## 7. 低功耗运行与按能量安排工作

**功能目标：** 将电量用在有效测量和必要通信上，减少无意义运行。

- 未来在非工作时进入低功耗等待，采样或上传时再唤醒相应模块；具体 STM32 休眠、唤醒和驱动尚未实现。
- 开始测量前检查是否有预算完成整个协议；不足时延期，不能擅自缩短恢复观察时间后仍沿用相同判定规则。
- 根据储能情况研究正常、降级、停止及恢复行为，减少非关键动作。
- 通信失败时限制尝试次数和能量支出，采用间隔重试，避免持续连接耗尽电池。
- 对比固定周期与按需采样的能量、等待时间和证据连续性，明确省电的代价。

**现有证据：** 已有秒级能量账本和完整动作准入仿真、纯 C 能量原语。按需请求仍是合成外部输入，未实现实际触发器；通知原型尚未接入这套无线能量调度。不能据此给出真实整机功耗或续航天数。

依据：[能量调度](ENERGY-SCHEDULING.md)、[纯 C 核心接口](CORE-INTERFACE.md)。

## 8. 电池运行与人工充电（当前候选）

**功能目标：** 用可充电电池支持晾衣监测，按储能安排测量与联网，明确提示需要人工充电。

- 研究电池、人工 USB 充电、保护和稳压路径，器件与接口未冻结。
- 未连接外部电源时按电池储能运行；光照不增加电量，不借尚未发生的充电能量。
- 低储能时延期或减少工作，人工充电后按状态契约恢复观察。
- 未来显示电池和已连接充电状态；避免把充电热偏差当成衣物变干。

电池容量、化学体系、充电芯片和电量估算未冻结。续航需按测量/联网工作量核对，并验证峰值、压降、温度/老化及充电热。旧能量仿真仍是历史光伏情景；新纯电池与人工充电端到端验证尚未实现。

依据：[当前开发计划](NEXT-PHASE-PLAN.md)、[历史能量调度](ENERGY-SCHEDULING.md)。

## 9. 家庭 Wi-Fi 与离家远程提醒

**功能目标：** 用户离家后，手机仍能获知有效监测结果。

计划链路为：衣架设备完成本地测量和状态判断 → 家庭 Wi-Fi 上传 → 服务端保存和分发 → 手机 App 接收与查看。STM32 负责测量与控制，独立无线模块是当前候选分工，具体器件尚未确定。

未来断网时，在供电和存储容量允许的前提下继续本地工作并暂存事件；远程提醒需等待连接恢复。局部断网期间不能承诺手机实时收到变化。

**现有证据：** 电脑上已连接真实 Python 研究状态机、本地持久队列、模拟服务端和接收端。尚无真实 Wi-Fi、账号认证、云服务或手机后台推送，模拟接收不能表述为手机送达。

依据：[离线提醒契约](NOTIFICATION-CONTRACT.md)。

## 10. 断网补传、重复抑制与过期提醒管理

**功能目标：** 网络恢复后，优先呈现当前状态，减少旧消息造成的误解。

- 每个事件有身份和版本，重发同一事件不会变成多次提醒。
- 重新连接时先同步最新状态；旧事件可以补入历史，但不能把新状态回滚。
- 换衣、开夹、重启或配置改变后，让旧提醒按最新状态失效。
- 有效期以原始证据时间为依据，重传、重新打开 App 或定时刷新不能让旧证据变新。
- 分开记录服务保存、推送通道接受、接收端保存和用户已读，避免把“已上传”显示成“用户已看到”。

电脑原型已验证这些协议行为，也验证了部分进程中断恢复。当前队列耗尽会锁存停止，并保留用于取消旧提醒的安全快照；这是有界原型的保护行为，长期回收和恢复方案尚未完成。

服务端无法知道设备离线期间尚未上报的变化。超时与重连同步只能降低旧状态风险，不能保证撤回手机上已经出现的系统通知；真实物理掉电和 Flash 存储也未验证。

## 11. 手机 App 的计划功能

用户已确认需要 App 远程提醒。下面是为支持这一需求提出的界面功能建议，**目前没有成品 App，完整页面和数据字段还未实现**。

| 页面或功能 | 计划展示／操作 | 当前边界 |
|---|---|---|
| 当前状态 | 当前监测结果、原因、需要等待或检查的事项 | 本地接口已有研究状态；不能显示“已干” |
| 监测对象 | 本轮衣物／测点的用户备注、是否需要重新安装 | 身份域已有软件规则；备注与完整交互待实现 |
| 温湿度与趋势 | 局部与环境温湿度、差异、随时间变化 | 现有合成原始记录；完整历史服务与图表待实现 |
| 数据新鲜度 | 证据测量时间、状态确认时间、最近通信时间，过期或未知提示 | 接口已有对应时间；不是完整采样历史 |
| 提醒记录 | 提醒内容、有效性、发送阶段与已读情况 | 电脑接收端已模拟部分行为；手机端未实现 |
| 电源状态 | 电池／充电状态、低电量降级说明 | 尚未接入通知接口；真实估算方法待验证 |
| 联网与绑定 | 配网、设备绑定、离线状态、重新连接提示 | 只有本地模拟绑定；真实认证和配网待实现 |
| 设置 | 允许调整的工作偏好，配置待应用／已应用状态 | 协议能区分要求与实际配置；手机控制链路待实现 |

当前通知接口中的 `measured_at_s` 仅表示最后有效弱证据周期的时间，不能充当“所有测量中最近一次测量时间”。强信号、开夹或故障清空弱证据后该字段可为空，界面不能因此显示“从未测量”。

未来产品提醒可以说明所测位置和判断范围，例如“所测位置达到已标定的提醒条件，建议检查收取”。这是待标定后的文案方向；当前研究提醒固定为“研究：需独立复核。弱信号尚未确认，不是收衣建议。”

## 12. 可解释提示与配置管理

**功能目标：** 让用户和开发者知道为何等待、为何没有提醒，以及某项设置是否真正生效。

- 在条件不明、数据过期、安装变化或供电不足时，说明对应原因，避免用一个笼统“干／湿”结果掩盖问题。
- 用户请求的新配置与设备实际应用配置分开记录；不能在设备仍使用旧设置时显示“已生效”。
- 影响测量方法的配置改变后重新开始证据收集，防止混用不同参数得到的结果。
- 保留必要的状态和事件记录，支持复现测量异常和通知问题；长期存储容量、回收和隐私方案需后续设计。

现有研究软件已有部分原因码、配置快照和重放能力。电源提示尚未与通知链路连通，LED、蜂鸣器、实体按键等也只是后续交互选择，尚未确定为硬件必需项。

## 13. 支撑开发的验证功能

这些属于开发工具，不是面向家庭用户的额外卖点：

- 用可复现的合成情景比较协议、扰动、误差与状态变化；记录参数、种子和数据来源。
- 对原始事件进行重放，核对同样输入能否得到相同输出。
- 在电脑上编译纯 C 核心，与参考实现对照，为以后移植 STM32 提供基础。
- 模拟断网、重复和迟到消息、时间异常、队列耗尽与进程中断。
- 用源码和产物指纹检查旧验证记录是否仍适用于当前文件。

纯 C 核心尚无 HAL、传感器驱动、实际低功耗模式或完整板级固件；其内存、历史容量和持久化仍需进一步处理。软件检查通过只证明被检查的软件行为，不证明衣物判干准确率。

## 14. 当前最值得形成优势的方向

本项目的可检验价值在于：把环境参考、局部动态观测、已知扰动后的证据重建、能量约束和提醒新鲜度放进同一个系统，减少“测到了一个湿度数值就立即发出结论”的问题。

但这些目前是设计重点和研究假设。后续应与单点环境湿度、被动局部差分等基线在相同条件下比较误提醒、漏提醒、等待时间、耗电和使用负担，才有依据判断复杂方案是否值得保留。不能仅凭模块组合或现有合成数据声称首创、准确率更高或优于已有专利。

本次功能说明不新增准确率、功耗、续航或测量间隔承诺。剩余干燥时间预测和雨情提醒现已由用户提出，处于新增设计阶段；全衣物含水率的实测能力、自动收衣、加热烘干和 AI 面料识别仍不是已确认实现。

## 15. 本说明的使用方式

对外介绍可概括为：**本项目拟开发一种安装于衣架的 STM32 衣物干燥监测装置，结合环境与局部温湿度观察、测量质量管理和低功耗调度，研究电池供电和人工充电下的服务能力，并通过家庭 Wi-Fi 与手机 App 提供远程状态和未来经标定的收衣提醒。**

后续实施顺序及未解决问题继续查阅 [ROADMAP.md](ROADMAP.md) 与 [STATUS.json](STATUS.json)。这次整理属于功能文档工作，不代替理论总审查、硬件实验或 App 实现。
