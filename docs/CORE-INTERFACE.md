# T06 纯 C 核心与主机验证

日期：2026-10-26。本文记录电脑端接口与适用范围，任务状态以 [STATUS](STATUS.json) 为准。当前没有 STM32 实机、驱动、传感器采集、远程推送或硬件持久化。

## 边界与结构

```text
可信采集／身份／时钟入口（未来设备层）
    ├─ 原始温湿度及质量标志 → measurement → 单周期研究判定
    ├─ 安装、启动、周期事件 → state → 多周期研究状态
    └─ 当前电量、负载与期限 → energy → 能量账本和任务准入
```

计算和状态更新位于 `firmware/core/`，不依赖 HAL、RTOS、网络、文件系统或 Python。主机桥接与对照位于 `firmware/host/`；模拟衣物、天气、网络和原始观测的 Python 环境属于测试输入生成器，不是设备上的测量算法。

上游依据为 [测量契约](MEASUREMENT-CONTRACT.md)、[状态机](STATE-MACHINE.md)、[能量调度](ENERGY-SCHEDULING.md)。原 Python 和已验收产物保持只读。C 的有界输入域、存储耗尽和时间上限须明确拒绝，不能把 Python 任意长输入静默截断后当成等价。

所有研究输出仍无收衣授权。连续弱信号、预算完成、质量有效和模拟联网确认含义不同，不能合并成衣物已干。

[hanger_core.h](../firmware/core/hanger_core.h) 给出独立的有界接口标识 `T06-C99-BOUNDED-1`。`hc_energy_protocol` 从已经通过完整校验的测量协议生成能量阶段，非整数阶段时长、非法配置或空输出明确拒绝，错误时不改变旧输出。调用方每次改配置后都应重新投影；不能让两个模块各自维护一套未核对的测量时长。

## 主机构建与检查

在项目根目录运行：

```powershell
# 使用现有 GCC，实际编译并执行；不覆盖主测试收据
python -B -X utf8 firmware/host/run.py --compiler 'C:\msys64=\ucrt64\bin\gcc.exe'

# 协调验收时写入与当前来源绑定的主收据
python -B -X utf8 tools/project_status.py --record-core-tests --check

# 以后恢复项目，只检查来源与已有证据是否仍匹配
python -B -X utf8 tools/project_status.py --check
```

编译器依次从显式 `--compiler`、`CC`、PATH 中的 gcc 及本机已发现路径选取；不下载或安装。`CC` 是一个可执行文件路径，不能包含一串 shell 参数。构建产物在被 Git 忽略的 `firmware/host/build/` 内，不修改原研究产物。主检查依次执行两角色的真实 C/Python 对照及协调者独立的链接边界检查；零检查、失败、异常或运行期间来源变化都不算通过。

正式证据记录编译器版本与目标、实际参数列表、检查数量、误差、结构大小及来源指纹。独立链接检查以 `-O0`／`-O2` 两种优化运行相同边界，另保存主机对象节大小和 `-fstack-usage` 输出。主机 ABI、优化和数学库的结果不能替代 STM32 的交叉编译、链接映射、完整调用栈或运行时测量。

## 测量接口

接口位于 [hanger_measurement.h](../firmware/core/hanger_measurement.h)。`hm_assess` 接收调用方持有的原始观测数组、协议和 Gates；`hm_result` 返回研究类别、原因位集、特征是否可用、恢复幅度和尾窗差。`collection_authorized` 始终为 0。错误原因位对应原测量契约；结构错误不计算特征，环境条件不合适时仍可保留诊断特征。

时间、温度、湿度、分压差使用 `double`，单位分别为 s、°C、%RH、Pa。C 没有 Python 动态类型；传输桥接将缺字段映射到 `present` 位掩码，将非数值测量映射为 NaN，将无效布尔类型映射为 0／1 之外的值。未声明的诊断真值不进入核心。协议身份解析为实际不可变协议参数并逐字段比较；不能把任意同名哈希视为正确配置。生产端仍须实现可靠的版本／身份解析，主机桥接不是通用 JSON 解析器。

当前边界为每周期最多 `HM_MAX_SAMPLES=512` 行、协议总时长不超过 86400 s、采样周期不小于 0.001 s，且计划样本数也须符合容量；具体关系以验证函数为准。最多 512 行不表示可以任意遗漏到该数量。超容量返回 `HM_CAPACITY_ERROR`，非法配置返回 `HM_CONFIG_ERROR`；无效观测仍返回正常调用状态 `HM_OK`，但研究结果为 UNKNOWN。调用方不能仅检查返回码就认为数据有效。

核心不保留观测指针，不分配动态内存；输入数组由调用方提供。当前主机单条观测为 80 字节，默认 141 行约 11.0 KiB，512 行上限为 40 KiB；这是主机 ABI 的输入缓冲成本，不能仅以小型输出结构估算整机 RAM，也不能据此声称已适配任一低成本 STM32。

## 能量与调度原语

接口位于 [hanger_energy.h](../firmware/core/hanger_energy.h)。它不拥有测量事件队列，不生成物理环境，也不执行完整 T05 仿真器。

| 接口 | 作用及调用方责任 |
|---|---|
| `he_config_validate`、`he_protocol_validate` | 验证本层能量参数和正整数阶段时长；完整测量协议仍由测量层校验 |
| `he_budget` | 完整测量或最坏无线尝试预算，分别输出动作、背景与电池侧需求 |
| `he_account` | 按固定 11 类负载优先供给，输出实际未供、转换损失、弃能及储能；脉冲不得附带未来收能 |
| `he_power_update` | 停止／低功耗／正常模式迟滞与付费启动；外部控制器实际执行开夹、取消和新安装语义 |
| `he_admit` | 供电、安装、批次、低优先级、完整期限、状态就绪、预约窗口、电量与无线额度准入 |
| `he_wifi_check`、`he_wifi_charge` | 最坏尝试的跨日额度检查，与实际付费时长的支出分别处理 |
| `he_quota_init`、`he_quota_advance` | 调用方拥有的当前／下一日额度结构；信任恢复值和时钟，拒绝倒退 |
| `he_retry`、`he_time_add` | 失败后的限次退避及有检查的无符号秒数加法 |

能量为 Wh、功率 W、开闭窗冲量 J；`store`／`battery`／`solar`／`spill` 为电池侧，其余负载项为负载侧。时间为 `uint64_t` 整数秒，阶段为 `uint32_t` 秒；超出表示范围拒绝，不能直接把 Python 任意精度整数强制转换。双精度数值须有限、非负，并满足配置关系。错误时不修改输出和可变状态；正常准入拒绝则返回 `HE_OK` 加拒绝原因，不能把 `HE_OK` 当成准入成功。

无线超时上限为一天，因此任一尝试至多跨两日。额度结构只保留当前日与下一日，并保存单调时间下限；跳过的旧日可以丢弃，不能倒退到旧日重获额度。检查不预扣假想支出，但推进可信时钟下限；实际收费才累计，结束时间排除在收费区间外。逐秒相加最多 86400 次，保留与 Python 的门限加法顺序；有界不等于实时耗时已经满足设备要求。

真正掉电后不能把额度清零再宣称恢复正确；缺少可信恢复数据时保留未初始化状态，无线检查会拒绝。没有实现非易失存储、原子写入或 RTC。单个活动任务、重复收费防护、跨模块协议一致、批次身份和完整 T05 事件顺序仍由外部控制器保障。

## 多周期状态接口与容量

[hanger_state.h](../firmware/core/hanger_state.h) 中 `hs_init` 初始化调用方拥有的状态对象；`hs_handle` 接收事件并返回 `hs_output`。函数返回 1 只说明输出已生成，是否应用事件必须查看 `accepted`／`disposition`／`reason`；空 API 参数返回 0。初始化失败使对象不可用，事件错误按 T04 定义拒绝或清空证据进入 FAULT。缺失的时间或窗口用 `has_*` 区分，不能把 0 秒当作缺失。

事件包含实际完整配置快照、原始观测和启动／批次／安装／周期身份；接收者核对当前配置，`configure` 必须携带旧上下文和新配置。阶段、门限或 Policy 改变会清空旧证据并要求重新安装。语义字段的内部 SHA-256 用于重复与内容冲突检测，指针地址和结构填充字节不进入摘要；它不是消息认证，也不是 Python JSON 字节格式的可移植签名。

| 固定上限 | 当前值 | 超限处理 |
|---|---:|---|
| 身份 | 32 个可打印 ASCII 字节，无首尾空格 | 拒绝，不能截短为另一个合法身份 |
| 事件历史 | 64 条，跨 boot 保留 | 新记录耗尽后锁存 FAULT |
| 周期身份／弱链 | 每 boot 16 个 | 耗尽锁存，不靠淘汰旧身份继续计数 |
| 启动身份 | 8 个 | 耗尽锁存 |
| 安装身份 | 每 boot 32 个 | 耗尽锁存 |
| 退役批次 | 每 boot 16 个 | 耗尽锁存 |
| 单调时刻／派生终点 | 0–1e9 s，派生期限须严格增加 | 拒绝非有限、越界或不可表示的期限 |

达到容量的最后一个合法记录允许；容量刚满时已有消息的相同重发仍幂等。再出现新记录并锁存后，boot、recover 和 configure 都不能解除锁存；证据与 pending 清空，绝不输出收衣。真正冷初始化会清历史，所以它只能在外部保证全新可信启动身份时使用，不能作为正常运行中清掉防重放记录的捷径。

这个配置是有界验证原型，**没有长期运行的历史回收方案**。例如每分钟发送一个 tick 时，64 条消息容量很快就会用完；实际寿命还受安装、测量、恢复事件影响，不能把容量耗尽锁存当作可直接交付的产品行为。本机 `hs_machine` 为 9616 字节，默认 141 行输入加状态对象已达 20896 字节，尚未加输出、配置、能量结构、调用栈和设备驱动。换芯片之前还需压缩身份／观测、流式处理或可信序号水位等专门设计与验证。

## 数值语义、一致性域与证据

C 测量遵守原强／弱与环境门限，没有扩大门限或把数值差异忽略为相同分类。初版扩展精度累加在精确门限附近暴露均值舍入差异，现改为固定整数累加器：将已经计算出的 binary64 分压差按 `2^-1074` 单位累计正负整数，求精确有理均值后一次舍入。36 个 32 位字覆盖最多 512 项、单项绝对值小于 `2^14` Pa 的输入范围，无需堆内存；两个累加器和辅助整数数组的栈成本也需计入。该范围来自受限温湿度换算，不能将内部函数直接用于任意大的浮点数。

这解决了已见的求和／均值舍入反例，没有证明所有平台的 `exp` 都返回相同比特。主机对照要求类别、原因、关键时刻与状态逐项一致；数值特征单独采用 `1e-10 Pa` 绝对容差，不能用数值容差豁免类别差异。这个容差针对计算，不是传感器或判干精度。换编译器、目标架构、数学库或浮点编译参数后必须重新运行精确门限和相邻浮点值检查。

测量实现要求 8 字节 binary64 和当前浮点环境为 `FE_TONEAREST`；不满足时编译或配置校验拒绝。目标 C 库需提供所用数学及浮点环境接口。主机验证禁用 fast-math／浮点融合，不把环境切换测试留下的舍入模式带入后续计算。

能量数值比较采用绝对／相对各 `2e-12` 的容差，离散准入原因和功率模式仍精确对照。在构造的远小于 `1e-12 Wh` 储能域，Python 参考的 epsilon 可能许可未真正付清的启动；C 另核对已供启动负载，无法付清时显式报错且不修改输出。这是有记录的保守差异，不把它列为完全等价输入域。普通默认及随机合法功耗域的离散决策仍要求一致。

Python 动态类型和 C 类型系统也不是完全同域：身份长度／字符集、计数范围、样本容量、时长、固定四槽退避和最多两日的尝试跨度都已限定。适配器必须在转换前检查整数类型和范围，例如 `2**32+3` 不能变成合法计数 3。C 签名摘要按规范化后的类型数据计算，不能保证区分原 JSON 的 `1`／`1.0` 或不同的非法文本；传输层若需要字节级冲突检测，须单独保留其语义。

正式通过情况和实际数值／内存结果见 [T06 协调审查](verification/T06-review.md) 与 [主机收据](verification/core-tests.json)，由真实构建生成，不能从本说明推定测试已运行。两角色报告分别为 [测量与状态](team/reports/measurement-t06.md)、[能量原语](team/reports/energy-t06.md)。独立协调检查覆盖跨模块协议投影、原始观测无效、能量边界、状态历史容量／冲突／重装、SHA-256 已知向量、510 组有理均值对照及失败收据处理。

主机固定结构、对象节和单函数栈帧只属于可复核资源测算；最大单帧不是总调用栈。数学库、中断、驱动、RTOS、通信缓冲、非易失存储和 MCU 链接布局均未纳入。核心无需动态分配，但本轮没有声称具备长期运行、完整 T05 事件控制器或可刷写 STM32 固件。

## 设备层仍需承担的责任

- 原始记录的类型、单位、时间关联和传感器错误必须如实传入，不能默补有效值。
- 提供可信的批次、安装、周期及启动身份；配置一致性指纹不构成认证。
- 按协议执行动作并提交原始观测，按时提供时钟事件；纯函数不会驱动风机或自行启动定时器。
- 真实掉电恢复、原子存储、RTC 连续性、日额度保留、队列、任务并发与网络确认需另有设备层约束。
- 实际堆栈预算、double 运算成本、功率、峰值供电及判干标定尚无实物证据。
